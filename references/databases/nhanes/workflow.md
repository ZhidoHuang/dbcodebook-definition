# NHANES 执行差异

沿用公共阶段规则，不新增独立执行流程。

1. 从[数据库差异](profile.md)确认来源类型及身份列。开发者入口使用已绑定当前网站的本地字典。
2. 批量选择写成 `RIAGENDR (常规(唯一SEQN))=sex`。固定网页入口核对来源类型、变量和别名。
3. 下载恢复入口使用 `--database nhanes`。按[文件契约](profile.md)核对每个来源文件的默认列、来源字典与原行；普通表检查个人—周期唯一性，明细允许一人一期多行。
4. 公共生成器使用 `database="NHANES"`，显式传入已核实的 `cycle_order`。仅在渲染副本中把 `YEAR` 投影为 `year`；交付表保留原身份列。
5. 默认 `SEQN`、`YEAR` 实际参与定义判断时，保留在正式来源映射中；生成器将其作为默认字段解析，不加入手选来源或原始变量总数。
6. 按公共结果检查与网站同步规则交付。旧文章更新保留原文章编号。

选择明细时使用完整身份，例如 `PADLEVEL (PAQIAF)=PADLEVEL`、`RXDUSE (RXQ_RX)=RXDUSE`。同一份已定清单可以同时包含普通来源和明细来源，下载包按来源类型分文件。

公开R分别读取每个实际源文件。普通主表与明细表均在读取时将 `SEQN` 和实际存在的 `YEAR` 保留为字符；不修改原始CSV。明细的 `DOC_FILE`、`RowIndex` 可以按字符保留。明细缺 `YEAR` 时，在公开计算区列出已核实的 `DOC_FILE`→周期映射，派生到工作对象，先检查未识别文件名和周期冲突，再汇总。

按已定方案汇总明细，检查汇总后 `SEQN`、`YEAR` 唯一，再连接工作对象；不直接将原始明细连接到主表。完整成果检查的文件清单须包含本包全部明细CSV。

明细汇总后以宽表连接主表时，完整工作簿保留实际参与计算的汇总列；分析工作簿仍只含身份和最终结果。在来源记录的 `source_summaries` 中逐列记录 `variable`、`source_variables` 和 `method`，完整字典的 `processed_vars` 追溯到对应原始明细字段。原始明细CSV保持完整，来源计数和最终结果映射仍使用原始来源。完整检查核对汇总列及字典对应关系；汇总数值是否正确，由R复核和独立结果核对验证。

`YEAR` 保留完整范围，如 `2017-2018` 与 `2017-2020`，不能转换为单个年份或合并两个重叠周期。摘要及图表均使用原周期标签。

药物分类专用入口不沿用普通来源的选择或字典契约。创建变量后，使用 `nhanes_export_contract.build_medicine_download_action` 生成动作，交给既有 `playwright_session_action.py --mode download` 执行。动作核对页面上的变量名、分类方式对应列表和所选分类；服务器拒绝导出时结束本次接收，不继续空等。

用 `validate_medicine_package` 检查独立药物ZIP及其 `raw_drug.csv`、`raw_drug_detail.txt`。该CSV按 `SEQN` 连接，不要求 `YEAR`；连接前确认 `SEQN` 唯一，连接后确认主表没有扩行。保留原包和分类说明，不把药物字段加入普通来源的提取清单。来源记录用 `medicine_export` 保存创建规格、实际参与计算的 `used_fields` 和连接键。完整字典保留这些药物来源；生成器通过 `medicine_codebook` 接收独立分类说明，生成药物专用提取入口。普通提取清单仍只含普通来源。完整检查核对药物原包、原文件字节和实际使用列；数值匹配仍按主题方案验证。

受限数据及上述契约以外的来源未接入。其他设备的网页来源探索仍需实际验证。
