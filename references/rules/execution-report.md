# 执行报告

执行报告用于回答四个问题：这次做了什么、每个环节用了多久、发生了哪些 Bug 或异常、任务最终停在哪里。它是过程证据，不进入正式笔记或网站正文。

## 何时创建

新建、重做或实质修改一个定义主题时，在第一次实质操作前运行 `scripts/execution_report.py init`。已有成果的网站同步使用 [Skill 的网站入口命令](../../SKILL.md#website-only-commands)：本地成果和浏览器登录在计时前预检，`verify-ready --start-sync` 复核成果后自动开始或继续 `website_sync` 计时，不再单独执行 `init` 和 `stage-start`。只回答问题、只读查看或不改变主题成果的简短审核不创建报告。

报告保存在主题执行目录：

- `execution_report.json` 是唯一事实来源，由脚本维护。
- `执行报告.md` 由同一脚本自动更新，供用户阅读，不手工填写。

已经存在执行中的报告时不得静默覆盖。继续原任务就沿用该报告；确实开始一次新的运行时，先结束旧报告并保留其真实状态。

网站入口复用同一主题仍在执行的报告；已结束报告由现有脚本归档后开始新运行。重复调用入口保留原同步起始时间，不重置计时。发布前核对失败会自动记录原因、结束失败环节并停止报告，且不操作网站。同步成功或浏览器失败后的收口仍使用 `stage-finish`、`issue` 和 `finish`；不手工追加一个脱离报告脚本的“同步完成”字段或Markdown段落。

## 必须记录的环节

根据实际任务记录以下环节；没有发生的环节标为“未执行”，不能伪造耗时：

1. 任务定位与既有材料检查。
2. 来源探索和权威材料核对。
3. 定义逻辑只读复核。
4. 最终来源选择与下载。
5. 正式 R 编写、运行和成果生成。
6. 公开 R 只读复核。
7. 全文与普通读者复核。
8. 机器验证。
9. 已授权的网站同步。

每个环节开始时运行 `stage-start`，结束后立即运行 `stage-finish`。用 `--mode work|wait|rework` 区分实际工作、外部等待和返工；进入等待或排错时结束当前段，再开始对应性质的段，不能把长时间排错全部记作“机器检查”。记录实际执行者角色和模型；模型不可核实时留空，机器脚本写“机器检查”，不猜测模型。完成内容只写已经产生并核实的事实。

## Bug 与异常

发生以下情况时立即使用 `issue` 记录，不等到任务结束后凭记忆补写：

- `bug`：代码、规则、数据或成果存在错误。
- `abnormal`：流程偏离、工具失败、登录失效、文件状态矛盾或意外重试。
- `wait`：外部页面、下载、验证或用户操作造成的等待。

每条记录说明问题、影响、处理和当前是否解决。已经解决的问题仍然保留，不能为了让报告好看而删除。

“已解决”需要可核验的结果，例如数据包实际保存且校验通过；仅重连浏览器、换一种尝试或发出命令不算解决。绕过故障取得成果时，分清“本次交付已恢复”和“故障根因已修复”。发现历史记录误标时使用 `issue-amend` 更正并保留原因。计时跨越用户讨论或未分段排错时说明其范围，不把整段时间称为纯操作耗时。

会阻断下一步、需要用户动作或已导致重复尝试的异常，记录时同时向用户说明卡在哪、成果是否已改变和下一步动作；不等到结束才披露。一次失败先查明原因再继续，不在同一未变条件下重复尝试。

## 时间口径

审核者每次完成一批工作后，用原始子智能体日志更新当前报告，不手工估计审核耗时：

```powershell
& $Python -X utf8 scripts/execution_report.py review-import --process-dir $Process --log $AgentLog --role "定义逻辑复核"
# close_agent 实际成功后，再用同一命令增加 --closed。
```

只读取这个明确指定的子智能体日志，不扫描整个历史对话。程序按 agent ID 去重登记、按 turn ID 区分轮次，分别列出新建数量、处理轮数、已结束轮次运行时间、两轮间隔和关闭状态。两轮间隔可能包含主笔修改、讨论、下载或其它工作，不能自动称为审核等待或有效修改；具体修改仍由主笔阶段计时。历史复盘登记到当前复盘报告，保留原报告。存在已登记但尚未关闭的审核会话时，不允许把当前报告标为完成。

- 总耗时是从报告创建到结束的墙钟时间。
- 环节耗时由脚本按开始和结束时间计算。
- 网站同步同时记录预载 helper 的哈希，以及 `browser_action.run_script` 返回的 `dispatch_latency_ms` 和 `browser_elapsed_ms`。调度等待说明计时后多久真正执行固定程序，墙钟时间说明整个网站环节，浏览器时间说明固定写入动作；三者不得混写成“网站处理耗时”。登录检查和 helper 预载在计时前完成，登录等待另记为 `wait`。
- subagent 可以并行，因此各环节耗时不能简单相加冒充总耗时。
- 不估算没有计时的历史环节；需要补记时明确写“历史阶段，未单独计时”。
- 未计时历史写进说明，不创建一个几秒钟的已完成环节冒充历史耗时。报告重新初始化会自动归档已结束运行；执行中的报告必须先如实结束，不能强制覆盖。

## 完成条件

主题宣布完成前必须满足：

- 报告状态已经结束，不是“执行中”。
- 所有实际发生的环节都有状态和完成内容。
- 没有未解决的 Bug 或异常。
- 报告列出的最终成果与本次机器验证使用的是同一批文件。

报告缺失、仍在执行、存在未解决问题，或新 raw 与旧成果并存时，不能宣布完成，也不能把旧的发布就绪记录继续当作有效状态。
