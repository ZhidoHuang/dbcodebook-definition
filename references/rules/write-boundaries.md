# 定义任务角色与写入边界规则

## 适用范围

本规则适用于所有数据库变量定义、返修和正式重生任务。

## 允许写入

定义任务只允许写入：

1. 当前主题正式目录；
2. 当前主题执行目录；
3. 主题完成后需要原位更新的主题索引和定义验收台账。

除此之外的写入，必须拆成独立任务，并由用户明确批准。

## 定义角色

定义任务负责从现有来源中检索、选择、解释和定义变量，并生成当前主题的正式成果。它不是网站维护、数据库维护或上游数据加工任务。

定义任务可以：

1. 使用 dbCodeBook 已有页面和既有接口进行目录浏览、普通检索、变量选择和数据下载；
2. 只读查看网站源码、生产数据、官方材料、Harmonized 材料和既有定义，用于理解来源与核对事实。

通过网站正常浏览、检索、选择和下载时，由网站自行产生的会话、下载、积分或审计记录属于网站正常运行，不属于定义任务篡改数据。

## 禁止越界

定义任务不得：

1. 修改网站源码、网页逻辑、数据库脚本、生产数据库、生产数据或旧数据库副本；
2. 直接执行 SQL、ORM 写操作、迁移、导入、同步、修库脚本或文件级编辑，改变网站或数据库内容；
3. 因网站缺少变量而修改上游数据、网页、目录、下载逻辑或数据库生成逻辑；
4. 从本地 DTA、Parquet、旧下载包、既有主题数据、Harmonized 数据或其它数据库文件补列、拼接、替换或重建正式 raw；
5. 为绕过路径或写入限制创建、修改或删除 `SUBST` 盘符映射；
6. 修改其它主题，或把网站维护、数据修复和定义工作混在同一个任务中。

正式 raw 只能来自 dbCodeBook 网站本次实际下载的数据包。官方材料、Harmonized 数据和其它本地资料只能用于理解与核对，不能替代网站下载数据。

是否需要重新下载，只看最终来源清单有没有变化，不看主题是新建、拆分还是改名。来源清单中的变量、周期、文件、来源身份或最终别名只要有一项变化，就按改变后的完整清单从网站一次重新下载；不得筛选旧包或拼接补充下载。来源清单没有变化时，不因文案、展示、注释、主题编号或同一批 raw 上的实现调整重复下载。

## 下载结果与找回

下载事件是通知，不是文件是否生成的最终依据。触发一次导出后，先核对实际保存的文件；事件超时不能直接判为失败，也不能据此再次触发扣费导出。浏览器参数使用当前接口文档的写法，例如本次接口的等待参数为 `timeoutMs`，不是 `timeout`。

正常下载是变量选择任务的主流程。修复或验收正常下载时，必须从变量选择页点击最终下载按钮，并以本次新数据包完整落盘和校验通过为成功；下载记录中的“找回”只处理已经失败的既有记录，不能代替正常下载验收。

每次正常下载和找回均使用 [Skill 的下载入口](../../SKILL.md#download-commands)。确认完整来源及别名后运行 `--prepare-download`，再原样执行它返回的 `browser_action.run_script`。程序优先使用当前选中的匹配页，否则自行绑定唯一匹配的内置浏览器变量选择页，打开下载弹窗，先启动下载接收，再点击一次最终下载控件；取得浏览器返回的本地路径后，直接用 `--archive` 校验并安装。只有浏览器没有返回路径时，才原样执行准备命令返回的 `watch_command` 检查实际保存目录。`$Downloads` 必须是浏览器实际保存目录，已有正式 raw 的有意替换才加 `--overwrite`。

从启动下载接收到取得路径期间，保留原页面，不刷新、导航、关闭或操作其它标签。等待 Promise 必须立即附加错误处理，避免超时导致浏览器连接被重置。浏览器路径和 `watch_command` 都只是寻找文件的方法，只有数据包通过变量清单与包内 CSV 校验才算下载成功。

程序只接受相对快照新增或发生变化、已稳定且完整校验通过的数据包；旧包、临时文件、来源不符或多个匹配包都不能被随意选为结果。按 `next_action` 执行：

| 文件观察结果 | 接着做什么 |
| --- | --- |
| 文件校验通过 | 直接继续定义，不再等事件、找回或重下 |
| 新出现的临时文件尚未完成 | 在原页核实下载进度；仍在下载就沿用原快照继续观察，不另做快照或发起找回 |
| 没有匹配文件 | 查看本次已有下载记录，再决定是否找回 |
| 多个匹配文件 | 先辨明本次文件，不自动选最新一个 |

所有观察结果都不会自动授权或触发重新付费导出。表单来源仍按网站的 `变量名 (来源文件)` 格式输入，别名以最终清单为准。

没有取得文件时，在同一内置浏览器查看账号的下载记录，按本次时间、数据库、完整来源及别名核对记录。已有对应记录就使用其“找回”入口，不重新导出。找回是直接文件链接时，同样先启动 `waitForEvent("download")`，再对刚核实的链接调用 `downloadMedia()`，随后读取 download path；不能把“已找回”当作文件已经落盘。浏览器仍未返回路径时再检查实际下载目录；若页面已显示“已找回”但尚未拿到文件，保留这一事实，不继续消耗其它找回机会。

已明确文件路径时，用现有 `recover_dbcodebook_export.py --archive <本次数据包> --database <数据库> --out <正式目录> --expect-vars-file <download_selection.txt>` 校验并安装；文件观察模式已经完成安装则不重复运行。变量清单和包内 CSV 校验通过才继续定义。找回当前任务已生成的数据包不属于从旧主题重建 raw。重试付费导出前必须先解释已查到的下载记录与文件状态；状态不明时停止导出，不猜测网站仍在生成。

用户已经明确授权付费复测时，确认上一轮未成功且没有仍在进行的下载后，沿用授权按上述步骤逐轮复测，不重复要求确认。“修下载执行流程”或“允许扣积分测试”不授权修改网站源码、重启网站服务或更换浏览器。

## 来源缺口

如果 dbCodeBook 的正常目录浏览、普通检索和页面下载不能提供所需来源，定义任务必须停止并报告缺口，不能自行改造网站、修复生产数据或从本地材料补齐后继续。

如果确实需要修改网站或上游数据，应结束当前定义任务，另行建立维护任务，并取得用户明确批准。维护完成后，再从网站重新检索和下载，重新开始定义。

## 网站发布

变量定义与成果生成阶段不能提前写网站。当前请求已经包含“更新网站”“同步网站”或完整“文案审核”时，机器闭环和全文审核通过后直接进入网站检查同步阶段，不再重复询问确认；请求明确限定为只处理本地成果时才停止在本地。已有审核成果的同步直接使用 [Skill 的网站入口命令](../../SKILL.md#website-only-commands)：先用不带 `--start-sync` 的 `verify-ready` 检查发布许可和四份成果，再确认现有内置浏览器标签仍已登录且文章身份正确；只有这两项通过后才运行 `verify-ready --start-sync`。只同步时不重新加载定义规范、问卷或数据库探索流程。

网站发布只能使用网站现有的正常发布页面或已经批准的发布接口。不得为了节省时间直接执行 SQL、Django ORM、数据库文件编辑或临时同步脚本；网页编辑器超时、附件较大或正常发布失败都不构成绕过理由，应停止并报告具体阻塞。

dbCodeBook 的网页探索、变量选择、下载和网站同步统一使用 Codex 内置浏览器。优先复用当前任务中已经打开的 dbCodeBook 标签页；不存在时才在同一个内置浏览器中打开一个标签页。不得查找、接管、启动或切换到 Google Chrome，也不得使用 Playwright 默认 Chromium、临时访客配置或其它浏览器会话。

必须在开始需要账号的检索或下载前确认登录状态；网站同步则在运行 `--start-sync` 之前，通过目标文章页上的登录身份和编辑入口确认。固定程序进入编辑页后仍须再次核对文章身份，核对通过前不得清空正文、移除附件或改动表单。既有文章因主题调整需要改标题时，两个网站入口命令必须传入同一个 `--website-title`；固定程序先按文章编号、数据库和旧标题核对身份，再在正文和侧栏附件所在的同一次提交中更新标题，不额外提交。未登录时停在尚未改动的内置浏览器页面完成登录；登录有效后继续原任务，不重新询问是否同步。

### 唯一浏览器执行程序

网站同步不得临场组合 CUA 调用。计时前的发布入口必须同时接收文章编号和配置中的站点地址，并返回 `browser_action.existing_tab_match`、固定载荷、helper 哈希及 `browser_action.preload_script`。确认匹配的页面已经在当前登录的 Codex 内置浏览器中打开后，原样运行 `preload_script`；程序优先使用当前选中的匹配页，否则自行找到唯一匹配标签并完成预检，只定义固定函数，不操作网页。`--start-sync` 只返回相同 helper 哈希、带开始时间的固定载荷和短 `run_script`，其后的下一次 CUA 调用必须原样执行 `run_script`，程序再次自行绑定该标签；中间不得另行绑定、解析长脚本或检查其它内容。缺少脚本、文章编号、站点地址、可确定的匹配标签或 helper 哈希不一致时停止，不猜测 API，也不手工重写脚本。固定程序如果在计时开始后 60 秒内仍未执行，必须在写入前拒绝本次同步。

固定程序在写入前核对编辑页地址和标题身份；写入后核对正文 UTF-16 长度、首尾及侧栏附件名称顺序。附件控件一次选择多个文件时可能自行按名称排序，因此程序固定按 `analysis_db`、`analysis_codebook` 逐个选择，每次文件选择器只接收一个路径。任何提交前检查失败都重新载入同一编辑页，丢弃未保存表单并停止；不换方法、不重试。程序必须返回调度等待、浏览器总耗时、打开编辑页、身份核对、正文导入、附件处理、提交返回五段耗时，以及编辑页、标题、正文、附件顺序、文章返回五项检查结果。执行报告另行记录网站阶段最终墙钟时间，各类时间不得混写。

### 固定步骤

新主题使用同一程序的 `--create` 分支，传入完整网站标题和已核实的目录标签，不传文章编号。先通过网站“写文章”入口进入空白表单；程序验证标题、正文和侧栏附件为空后才填写，提交后记录网站实际分配的文章地址。既有文章仍使用 `--post-id` 更新分支，不能用新建分支绕过既有文章身份检查。

1. **确认本次对象。** 明确文章编号、唯一编辑页、正式正文路径、网站目录标签，以及本轮是否需要替换封面或附件。目录标签只能沿用主题索引、验收台账或同一业务组既有文章已经使用的登记标签，不能从文章标题、主题中文名或英文名临时造新标签。上述信息没有同时明确时，不得开始浏览器操作。
2. **锁定一个已登录的内置浏览器编辑页。** 先复用当前任务中已经打开的内置浏览器标签并确认登录有效，再锁定唯一编辑页。一次同步从开始到网站返回结果只使用这一个编辑页。目标编辑页已经存在时继续使用，不再打开同一地址，也不新建窗口、标签或并行编辑会话。
3. **等待页面真正就绪。** 必须看到原正文、封面和附件列表已经载入，不能只看浏览器的“页面加载完成”。页面可能停在旧滚动位置，应先回到顶部并点击标题输入框激活当前编辑页，再读取可见控件。控件操作优先使用当前可见控件的原生点击；读取只返回按钮、文章身份和附件区域，正文只返回是否为空，避免把整个编辑框内容输出到上下文。点击后读取相关控件的变化，不复用已经变化的索引。导航是否成功以随后返回的页面状态为准，不以点击调用成功或点击后瞬时地址为准。
4. **一次替换正文。** 真实点击可见的“清空内容”，确认编辑栏为空；再真实点击可见的“导入正文”，一次选择完整正式 `.md`。导入可能是追加而不是替换，因此必须先清空；导入不会自动提交，同一次编辑中不得重复导入。
5. **只处理确实变化的文件。** 封面或附件没有变化时保留网站现有文件。定义笔记规定的 `analysis_db`、`analysis_codebook` 固定上传到“侧栏文档”，不得放入“正文文档”；附件变化时，先在尚未提交的表单中从原位置移除旧附件，再从可见的“侧栏文档”上传区域按 `analysis_db`、`analysis_codebook` 的顺序逐个上传。不得把两个附件放进同一次文件选择。只有正文明确包含 `[DOCUMENTS]` 且任务另有规定时，才可使用“正文文档”。不得为了测试流程重复删除和上传。
6. **提交前只检查一次。** 直接读取正文编辑框的字符数、开头和结尾，与入口命令返回的 `body_check` 对照；长度按浏览器的UTF-16字符单位计算，换行统一为LF。确认文章身份，不输出整份正文，也不再次读取本地正文计算长度或哈希。附件未替换时只确认原附件名称仍在，不调整历史顺序；本轮替换时才核对新文件名称和规定顺序。
7. **提交并停止。** 点击“发布”或“更新文章”。网站返回文章详情页即表示同步成功；发布后不再重新打开或检查正文、附件和详情页。

### 备用方式

只有可见的“导入正文”确实无法使用时，才允许人工粘贴。先用编辑器的“清空内容”按钮清空，再一次粘贴全文；不得使用 `Ctrl+A` 或全选删除，不得分段粘贴、循环拼接或在多次浏览器操作之间续写。Windows 剪贴板与内置浏览器剪贴板没有明确验证相通前，不得混用。

### 立即停止的情况

- 页面尚未显示原正文或现有附件时继续等待，不提前点击。确认页面已经就绪后，文件选择窗口仍未出现，才判定失败。
- 取消文件选择、文件为空、格式不支持、读取失败、正文不完整、本轮附件未出现、浏览器连接中断或已锁定编辑页失效时，立即停止。若尚未提交，重新载入同一编辑页，使页面恢复网站当前已保存内容，然后报告具体阻塞。
- 停止后网站同步仍记为未完成。只有用户重新下达同步指令，才从网站当前已保存状态开始新的一次同步。
- 总耗时从收到执行指令开始，到网站返回成功或明确停止为止，浏览器连接、失败和排查都计入。每次成功后必须同时汇报：五段浏览器耗时、浏览器总耗时、从网站阶段开始到浏览器返回的耗时、网站阶段最终墙钟；不得只摘录其中最短的一项。复用已登录会话时，浏览器总耗时以30秒内为目标，超过60秒仍未返回就停止；从网站阶段开始到浏览器返回以90秒内为目标，包含报告收口的网站阶段超过2分钟仍未成功就立即停止。需要登录的等待时间单独记录，不混进浏览器固定动作并继续尝试。

### 禁止动作

- 不直接触发隐藏文件输入框，不用坐标猜测上传入口，不用看似点击但没有真正打开文件选择窗口的合成调用。
- 不调用、查找或临时新建围绕文件选择窗口的通用上传器；已有可见控件可以完成的操作，不再包装新工具。
- 不连续重连、重复打开编辑页、反复点击、分段补写、改走隐藏控件，或在导入外层增加等待富文本完整渲染、循环读取正文等包装。
- 不在同步过程中用对象方法枚举、试错调用或临时 API 探索；固定脚本不适用时按失败退出，再单独修复 Skill 和测试。

## 执行方式

本规则约束定义任务实际执行的角色和行为，不要求为网站、数据库或源目录建立哈希基线，也不在每次 R 运行前后扫描它们是否变化。

正式 runner 只检查定义脚本、来源记录和正式成果本身。是否遵守本规则，以任务实际执行的操作为准；不能用机器检查未发现变化来替代角色边界。
