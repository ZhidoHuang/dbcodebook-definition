# 6. 结果验证

执行记录：本步 `stage_id` 为 `results`。

## 本步执行与验收

- 输入：当前生成成果、来源方案及实际路径统计
- 另读：所选数据库差异说明中的身份、时期、文件结构及验证范围
- 执行：按确定变量和身份键核对完整交付物，按风险复算结果及分支统计；记录实际执行范围
- 交付：当前版本的输出检查报告、主题复算/回归证据
- 程序检查：check_definition_output.py 的完整检查模式检查必需项；局部检查的 ok 只代表列出的检查，不代表完整成果通过
- 模型判断：未解释缺失、冲突、值域、单位和路径人数是否都有根据；不能用运行成功代替复算
- 未通过：退回出错的来源、R 或生成环节；变化后更新受影响证据，不交后置审核代为排错

## 完整检查入口

```powershell
& $Python scripts/check_definition_output.py --complete --db $Database --formal-dir $Formal --process-dir $Process --expected-files $ExpectedFiles --raw-vars $RawVars --analysis-db $AnalysisDb --analysis-columns $AnalysisColumns --analysis-codebook $AnalysisCodebook --analysis-vars $AnalysisVars --check-summary-facts --require-log-exit-code --report "$Process/result_check.json"
```

参数来自已定方案，不重新手写一份变量口径。ExpectedFiles 包含 raw、正式 R、笔记、四张工作簿及正式 HTML/QA 等本次交付物。报告绑定当前来源方案、检查程序和实际文件，进入成品交接前会核对它。文件变更后，只补做受影响的业务核对与复算；重新运行完整检查，生成绑定当前文件的报告。不受影响且仍有效的复算证据可以沿用，不因此重新探索。

不加 --complete 可做局部诊断，返回 PARTIAL_CHECK_PASS；不能用于发布许可。完整检查通过也不代替下面要求的业务复算与解释。

通过本步才交接给下一步；一次命令或点击不是一个独立验收环节。只读复核者接收本步稳定输入、对应标准及具体问题，不接收整个历史对话。

1. 正式 runner 成功，唯一最终日志含明确退出码 0。
2. 固定检查器使用正确数据库参数运行并为 `ok: true`。
3. 正式目录、raw/header/codebook、analysis、mapping、禁止变量、唯一日志和用户材料结构检查通过。问卷展示在生成后按[文案读取与展示](05-generate.md#文案读取与展示)及[问卷要求与模板](03-copy.md#4-原始问卷调查实际问了什么)核对，确保题前条件、完整选项及跳转说明清楚且与原问卷一致。
4. 按实际改动完成足够的回归或独立复算，能够证明变量值、缺失、覆盖、来源身份和输出结构符合当前裁决。对已发现的原始题目间矛盾，必须验证处理符合已确定方案：未经用户裁决时，各变量按各自直接来源保留，不得擅自协调或覆盖；已有明确裁决时，验证其实施与方案一致。对每个定义变量和调查时期，按[第1步确定的来源及分支范围](01-source-plan.md#两个代理各自查什么怎样判断)，核对赋值、筛选和必要验证所用的直接回答、前置或预载信息及跳转，并统计各分支人数。方案允许合并的NA分支核实合并条件和总人数，不要求临时拆出各个缺失原因，也不声称各原因均已逐人识别。未知编码、直接回答冲突、与方案不符的结构性缺失或缺少必要字段仍须解决；不能用一个“其他NA”分支把这些问题算作已解释。
5. 新增或修改公共机制时，相关 fixture、专项扫描和既有主题回归通过。
6. 过程证据存在、非空、可读；正式目录不混入过程材料。

机器闸门任一失败时，执行任务必须自行修正或向大脑报告阻断。不得把未闭环成果转交验收任务代为排错。

读取工作簿使用 scripts/check_definition_output.py 的 read_xlsx_rows；它读取实际单元格，不能依赖可能错误的 A1 维度。独立复算依据已确定方案和原始记录，独立计算预期结果，再与正式成果比较；不能仅重跑正式R，或复制正式实现作为独立依据。文件读取工具可以共用，复算范围按实际改动和风险确定；独立复算不表示另增审核角色。

完整检查省略 --report 时默认写入 `$Process/result_check.json`。ExpectedFiles 未列正式 R 时，仅在正式目录有唯一 `define_*.R` 才自动补入；零个或多个时要求显式选择，避免检查错脚本。其它交付物与变量口径仍须明确。

## 来源重叠核对

多个来源在相同时期覆盖同一研究概念，且方案需要将它们视为等值替代或按优先级合并时，比较该时期对应记录的非空值与缺失模式，记录总行数、双方非空可比人数、双方均缺失人数、缺失模式不同人数、有效值不同人数及采用理由。首次比较在下载后、正式 R 前完成；本步沿用仍有效的证据，核对实现是否遵循方案。结果符合已定方案时继续；发现方案未解释的差异时返回来源环节调查，不用合并优先级掩盖问题，也不因已解释的差异固定要求用户重新裁决。不同对象、不同含义的来源不作等值比较。

## 名称与显示一致性

变量或Label更改后，核对analysis_vars、analysis_db、analysis_codebook、mapping、定义表、Criteria、Easy.label、组分概览/详情、定义卡、坐标轴、图例和公开R标题注释。显示语句可以不同，对象、方向、回顾期、单位及分类不能变；旧名残留或含义错配不得交付。分组按真实研究概念显式指定，不靠名称字符串猜测。来源标签说明原题，定义标签来自对应分析变量Label。
