# 4. 公开 R

## 1. 输入与交接

本步stage_id为public_r。依据当前raw/codebook、已确定方案、别名和定稿文案编写唯一正式R；特殊编码与分析单位读所选数据库对应部分，字典使用[现有模板](../../../templates/public-r-dictionary.R)。研究口径未确定或必要来源缺失时退回方案/下载，不在公开代码运行时才决定，也不把未下载写成调查未收集。

写完后先运行一次预检，集中解决问题，再按[复核交接](../review-roles.md#稳定输入到复核结论)完成一次依据当前合并方案的R实现只读复核。预检按ProcessDir及来源记录识别任务，不依赖正式目录是否带数字编号；检查来源、文案、环境、头部、字典及语法，不生成成果，也不要求尚未发生的独立复核：

```powershell
./scripts/run_r_definition.ps1 -WorkDir $Formal -Script $RFile -LogPrefix $LogPrefix -ProcessDir $Process -Config $Config -Database $Database -PreflightOnly
```

复核绑定稳定R、来源记录、raw_codebook、探索记录和必要证据；失败由原角色复核受影响修改，不再另派来源逻辑审核。正式运行前确认结论仍有效，运行自带检查，不再重复单跑预检。仅文案变化沿用未变R的有效结论；未完成独立复核不能以自查替代，可继续不依赖它的准备工作。公开R可由读者在RStudio全选运行，无需runner的过程记录；本流程正式运行前仍须完成上述独立复核。

正式runner将实际脚本、来源记录和raw_codebook与复核绑定输入核对；审核了另一个文件不能放行本次运行。公开代码未变时，后台或文案修改仍可沿用有效复核。

文案与已定方案不一致时，表达错误回文案；研究取舍尚未确定回探索；R未忠实实现已定方案则修R。交给生成环节的是稳定R、真实复核结论及已解决发现；代码解释在本步完成，第7步沿用，不再次逐块审核。

## 2. 公开区与后台区

唯一 `# 输出` 之前为公开代码：环境、读取、必要依据展示、重编码、跨期合并、变量构造，以及map、add_mapping、字典和四份工作簿写出。之后为后台QA、标签扫描、哈希/覆盖检查、HTML、detail、笔记和可视化。不能把计算移到后台规避复核。

每个分析变量通过 `add_mapping()` 登记全部参与定义的原始来源，由mapping生成codebook的original_vars、processed_vars及count，不直接手填。CHARLS保留模块身份，ELSA保留完整Variable (File)身份；来源别名不在R中修补。

前置跳题补值按已定方案先识别完整路径，再给对应结果赋值；判定所用的前置变量也登记到mapping。多题共同决定的条件不能因忽略缺项而误判成立；不把不适用、普通未答或无法确认路径的空白一起补0。有效直接回答与前置路径冲突时，按方案已定处理，不静默覆盖。实现测试覆盖满足补值条件、条件不满足、前置题缺项及适用时期之外；有不适用或回答冲突的分支时一并覆盖。

固定函数名、对象名和章节标记属于接口，不为改善措辞改名；在相邻注释解释含义。显示及后台生成接口见[成果生成](05-generate.md)。

## 3. 固定头部与读取

```r
rm(list = ls())

for (pkg in c("devtools", "openxlsx", "dplyr")) {
  if (!requireNamespace(pkg, quietly = TRUE)) {
    install.packages(pkg)
  }
}

library("devtools")
library("openxlsx")
library("dplyr")

install_github("ZhidoHuang/dbCodeBookr") # 提示更新包, 可选3跳过，首次使用时需要安装
library("dbCodeBookr")

dt <- read.csv("raw_data.csv")
name_z <- read.csv("raw_codebook.csv")

data <- dt
data[data == ""] <- NA
```

- 正式公开 R 直接使用 `read.csv("raw_data.csv")` 和 `read.csv("raw_codebook.csv")`。若 `id`、`householdid` 或 `communityid` 的实际值含前导 0，可只为这些身份列追加 `colClasses = c(... = "character")`，并在读取前用一句注释说明目的；Full HRS的 `HHID` 和 `PN` 按字符型读取，也属于允许指定 `colClasses` 的身份列，在读取时保留前导0，不在读成数值后补救。不追加 `fileEncoding`、`encoding`、`na.strings`、`col.names` 或 `check.names = FALSE`。

预检按 R 语法解析这两个读取赋值，空格、换行、引号样式及身份列顺序不影响结果；不要求为通过检查改成某个单行字符串。真正改变读取文件、额外参数或非身份列类型仍会被拒绝。
- 不用 `names(dt)[1] <- "ID"`、`names(name_z)[1] <- "Easy.label"` 或按列位置重命名修补导出问题。来源别名必须已经按 [来源别名](02-download.md#12-来源别名必须在下载前确定) 在下载前确定，并由正式 raw 和 codebook 原样带入。
- 读取区只读取数据、统一空字符串和必要基础类型。`raw_row_count`、完整性断言和覆盖统计放到后台 QA；不使用 `raw_vars <- name_z$newname` 绕行取得数据列。
- 读取区一级标题统一写为 `# ----------- 2 读取数据 -----------`。不在标题后追加“本次 dbCodeBook 导出”“网页导出”或其它来源说明；确有必要时，在标题下用普通注释说明来源。
- 已有全局空字符串处理时，不再默认清理字符串 `"null"`。具体变量需要清理时，依据已经核实的标签就地 `trimws(as.character(...))` 并重编码；必要的实际取值输出只作为依据展示，不承担现场决定口径的任务。

## 4. 业务顺序与注释

公开代码首先让具备基础 R 知识的读者顺着看懂每个变量怎样得到，允许适量重复，不以缩短代码为目标。按具体变量和实际判断顺序直接写出来源选择、赋值、补值和计算；不能为了批量生成少量变量而让读者追踪矩阵列号、动态变量名或多层调用。

代码按“主题总述 → 来源事实与定义决定 → 实现 → 结果检查 → 字典和输出”展开，不复演探索过程。简单变量可在同一小节说清，不为凑步骤拆标题。

| 位置 | 要说明的内容 |
| --- | --- |
| 主题总述 | 定义什么、原始记录为何需要处理、后续代码的主要顺序；只补真正有助理解的背景和关系 |
| 变量或业务小节 | 使用哪些来源及时期、真实标签/编码意味着什么、为何合并或分开、如何赋值/补零/保留缺失及完整性要求 |
| 非显然的代码块前 | 本段解决什么、输入是什么、得到什么、后续用于哪里；安装包、读取及简单赋值不逐行解释语法 |
| 结果检查 | 定义后用table()或summary()查看结果范围/分布，不凑前后说明 |

总述不照搬[笔记摘要](03-copy.md#3-摘要最终得到什么)，不写目录入口、版本修改过程、工具或审核记录。按最终变量或真实分支组织来源，避免一个开场讲结果、另一个开场重新盘点来源。综合主题先说明总体及组成关系，实际代码、Criteria与输出顺序仍为原始来源→组成变量→综合变量；综合Criteria只写组成、公式和完整性，不在每个分项重复。

年份、原始变量名、编码、公式和例外在实际使用的小节说明，总述不堆细节。反复按人物或项目提问时先说明对象与每次记录的信息；固定结构已核实且数量有助理解时才用乘法，数量须能对回总数，不从后缀推测人数。

注释用具体对象和自然语言解释判断，不用“按来源处理”等空句或维护者简称代替事实；辅助函数说明它反复处理哪些回答，变量对照表说明对应关系。必要术语解释其本题含义，不逐项重复已有清楚名称。

来源组在第一次参与处理处定义；多个并列变量共用的整理或中间结果在首次使用前独立准备，并说明后续用途，不藏在某个变量中。仅服务字典/输出的raw_vars留在输出阶段。中间对象首次出现说明内容。只有复用确实比逐项展开更容易理解时，才采用函数、循环或矩阵；加注释本身不能证明复杂结构有必要。确需使用时，就近说明输入、每轮处理和结果去向。

### 标题格式

用阿拉伯数字表达“大阶段→并列模块→必要的局部步骤”；同级模块粒度一致，不设空标题，不强凑三级。读取后首个主题业务块从第3阶段开始：

```r
# ----------- 3 定义【主题】变量 -----------
# 说明研究内容、定义变量及必要关系。

## 3.1 第一个业务模块 ####
### 3.1.1 必要的局部步骤 ####
```

## 5. 依据展示、清理与复用

- 原始变量组首次出现就地说明周期、题义和已确认的结论，再用str()、unique()、table()或summary()展示依据。相邻判断实际使用的原始变量须全部覆盖；变量多则按时期或分支分块，不让读者从多张无解释的输出自行推理。
- 探索候选、发现编码规律的代码留在探索记录；公开区只保留上述依据展示和定义后的结果检查。stopifnot、identical、未识别值与批量一致性断言放后台QA。
- 只根据实际raw问题转换或清理类型、范围、年月配对、单边缺失及特殊编码。数据没有问题时保留原值，不机械加suppressWarnings(as.numeric())或静默改缺失；未来输入变化用检查报错暴露。
- 重复规则先完整展示一个具体来源的“原回答→规则→结果”，再复用辅助函数/循环。函数只隐藏已解释的重复语法，不能隐藏归组、阈值、补零或跨期依据；放在规则之后、首次调用之前，说明输入、输出及复用理由。纯输出/排版/对照表工具不要求业务示例。
- 少量变量或时期优先逐项展开，直接使用有含义的变量名。原值整理确实重复时可复用单一用途的函数，但时期选择、补值条件和结果构造仍在调用处看得见。示例应参与正式结果，避免另外算一份演示对象，再用另一套代码生成成果。
- 少量分类值使用已解码的完整真实标签逐项重编码；大量同构变量才在说明每期编码含义并展示代表性映射后复用编码提取。不把裸数字或全局编码规律当作业务依据；具体函数限制见下节。

## 6. 函数用法

### recode.chr： `recode.chr()`

`recode.chr()` 是 RStudio 代码生成辅助，不是运行时清洗函数。

- 适用于真实取值已经核实的简单单变量重编码，例如 `recode.chr(data$raw_var)`；生成后按业务含义修改右侧并固化为逐项 `case_when()`。
- 它依赖已经解码的完整标签生成可审核映射；解码用于确认含义，`recode.chr()` 不负责发现题义、决定归组或判断跨周期能否合并。
- `# recode.chr(data$raw_var)` 只标记 `data$raw_var <- case_when(...)` 这种原位重编码；前面可放该变量的 `table()`。若输出是新变量（如 `data$result <- case_when(data$raw_var == ... )`），直接写映射，不加此标记，也不为满足标记而覆盖原始列。
- `table()` 中每个真实原值在相邻重编码块单独占一行，以 `==` 精确匹配。即使多个原值映射到同一结果，也不使用 `%in%` 压缩。
- 单次使用的原值集合不提前抽成 `standard_*` 或 `allowed_*`；稳定且被多个业务判断重复使用时才命名。
- 跨周期合并、多变量计分、汇总、阈值、回溯、正则或其它自定义逻辑不得贴 `recode.chr()` 标签；大量同构字段可在先展示一个具体映射后，用业务清楚的 helper 复用技术动作。
- 不使用 `grepl()`、正则、模糊匹配或泛化 helper 伪装成 `recode.chr()` 生成代码。
- 已核实取值很少的单个分类变量，不使用 `substr()`、`trimws()` 或提取首位编码绕开逐项映射；按上面的 `recode.chr()` 形式把完整原始值逐项写清。只有大量同构变量确需批量处理时，才在展示代表性映射后复用编码提取动作。

```r
table(data$var, useNA = "ifany")

# recode.chr(data$var)
data$var <- case_when(
  data$var == "原始值1" ~ "标准值1",
  data$var == "原始值2" ~ "标准值2",
  TRUE ~ NA_character_
)

table(data$var, useNA = "ifany")
```

### recode.num： `recode.num()`

- `recode.num()` 同样是 RStudio 代码生成辅助，只用于同一变量的真实原值到数值的转换。
- 标记同样只用于原位赋值；从原始列生成新变量时直接写映射，不加标记。正式 Rscript 不依赖函数运行期返回值。
- 只有 YES/NO 二分类默认使用 `1/0`；其它分类变量默认保留规范英文/ASCII 标签。
- 得分、合计、跨周期统一变量和阈值变量直接实现真实计算，不伪装成 `recode.num()`。

### yyds_coalesce： `yyds_coalesce()`

- 来源别名和合并资格必须已经按 [来源别名](02-download.md#12-来源别名必须在下载前确定) 在下载前确定。合并时，各来源必须使用相同编码表达相同含义。原始编码不同时，按探索阶段确定的对应关系重编码后，再调用 `yyds_coalesce()`；仅把编码改成相同数字，不代表来源可以合并。
- 函数按 `pattern` 和 `key_chr` 匹配列名，把去掉指定前缀或后缀等标记后同名的列分组，逐行取第一个非NA值；全部为NA时结果仍为NA。优先级按 `data` 中的实际列顺序，不按 `key_chr` 的排列；调用前把各来源列排成方案确定的顺序。多列同时有值时取靠前列，不自动判断冲突或校验合并资格。
- 默认 `remove_original=TRUE` 会删除参与合并的来源列；仍需用于 mapping、来源卡或重叠核对时，显式设为FALSE。`valid_var` 用于按指定列展示合并前后的非缺失数量，不负责判定能否合并；当前已安装版本省略它会报错，应传入实际分组列，如时期列。
- 调用处只用一句紧邻注释说明合并资格；各来源周期、优先级和特殊值在实际参与定义的位置说明。
- 已经确认可以合并的来源，正式 R 直接调用 `yyds_coalesce()`；不得再按年份手写一组 `case_when()` 重做同一件事。

```r
# 周期互补且含义一致的来源使用同一词干和 _1、_2 后缀
```
