# 3. 文案写作

- 根据已经确定的定义方案、官方材料和实际数据，在一份`文案.md`中完成下列内容。
- 本页说明各部分的目的、内容要求和格式；[文案模板与实例](../../../templates/reader-copy.md)按相同顺序展示写法。
- 完整写作前读取这两份文档；局部修改时读取两份文档中对应的部分。

## 1. 文案组成与顺序

按下表顺序填写`文案.md`。有条件的部分按实际情况写，不为凑齐栏目增加内容。

| 组成 | 让读者明白什么 | 何时填写 |
| --- | --- | --- |
| 标题 | 这是哪个数据库、什么主题 | 必填 |
| 摘要导读 | 定义哪些内容，共多少个变量 | 必填；结果关系按需另用关系树展示 |
| 定义依据 | 有哪些适用标准，为什么采用本次定义 | 采用量表、诊断、分类或综合指标的标准时填写；按下文决定展示一套标准还是比较多套方案 |
| 问卷 | 帮助理解结果取值所依赖的题义和提问条件 | 定义依赖跳题、多题关系，或原题能消除关键歧义时展示相关部分 |
| Criteria | 每个变量的含义、取值方法及必要限制 | 每个最终变量都填 |
| 小book提示 | 多组结果或整个主题使用时要注意什么 | 有这类提醒时填写；没有则使用约定的省略句 |
| 参考资料说明 | 定义方法有哪些依据 | 有实际使用的方法资料时填写；没有则省略该节 |

生成后的笔记会把小book移到问卷之后，并自动加入数据库目录入口、图表和附件；这些不用手写进文案。

### 通用表达

以下要求适用于摘要、定义依据、问卷说明、Criteria、小book和参考资料说明。

- 用具体对象和动作说明事实，像正常向读者解释问题一样写。可以使用必要的专业词汇；含义不明显时就近解释，不自创简称。
- 一句话表达一个意思。不同处理分句或分项写，条件和例外紧跟对应处理，不用长串分号压缩。
- 同一概念使用同一名称。名称已经清楚时，不再重复释义。
- 完整保留必要的时期、对象、条件和例外，不为短句删掉限定，也不机械限制句长。
- 同一信息放在最合适的位置；再次提及时应有不同用途。
- 全篇名称的对象、方向、时间和单位保持一致。
- 初稿依据本次已确认事实，不照抄旧稿；来源不明、方案未定时先解决事实问题，不在写作时自行增加口径。

### 通用格式

使用 Markdown，不手写 HTML 或 CSS。数字与量词间留一个半角空格，百分号紧贴数字。

正文中的原始变量名、最终变量名和程序代码使用成对反引号，包括表格说明、小book和问卷备注。单个变量写成 `db010`；多个变量分别标记，如 `db010`、`db011`。完整代码表达式或公式放在同一对反引号内，如 `ADL_count = ADL_dressing + ADL_bathing`。

以下位置不另加 inline code：

| 位置 | 写法与显示 |
| --- | --- |
| 问卷题目标题 | 写原问卷变量名题号，由生成器加粗 |
| 问卷跳题说明 | 条件和去向中的变量名题号用普通文字，如 → 跳至 C109 |
| 定义表、结果卡片中的变量标题 | 文案用纯变量名作三级标题，如 `### ADL_count`；生成器处理显示 |
| 可点击的来源映射区域 | 由生成器和网站处理，不在文案中手写 |
| 关系树 | 使用下文规定的语义标记 |

编码值、解码标签、回答选项、类别名称和中文结果名称使用普通文字，不用 inline code。按栏目要求加方括号时，写成 [0]、[No_difficulty]，不再套反引号；英文或带下划线的取值也按此处理。代码块内已是代码格式，不再套反引号。

### 写作前先判断两件事

1. **判断结果关系。** 区分共同测量同一概念、多个结果并列，以及多个成分构成综合结果。
   人口学的多个并列概念不因此成为综合指标；不能只按题目数量判断。
   关系树的使用条件见[摘要](#3-摘要最终得到什么)，问卷展示和分组见[问卷](#4-问卷调查实际问了什么)。
2. **判断是否有公认且适用的统一标准。** 核对已核实指南、原始方法或技术资料的人群、版本及数据适用性。
   只有一篇论文，或多篇论文引用同一框架，都不足以证明具体计分统一。
   展示一套标准还是比较多套方案，按[定义依据](#定义依据先说明标准再说明本次采用什么)处理。

使用文献和问卷已有的概念名称，不为上述判断增加新的主题分类名称。
不得自行发明概念、量表名称或标准，也不将本次内在能力的成分与算法套到其他主题。

## 2. 标题

**目的**：让读者识别数据库和主题。

**内容要求**：主题名称准确覆盖实际定义，不扩大范围，也不堆列所有变量。中文与英文含义一致。

**格式要求**：一级标题，使用“数据库 — 中文主题（英文主题）”，不加主题序号。

**模板与实例**：[查看本部分](../../../templates/reader-copy.md#2-标题)。

## 3. 摘要：最终得到什么

**目的**：让读者知道本主题定义哪些内容，共多少个变量。

**内容要求**：

- 尽量简短地介绍全部最终变量及总数。每个结果都要点到，允许用简短名称和适当归纳，不必重复完整名称。
- 同类变量按结果维度分组。共同名称放在括号外，括号内用短语列出各变量的对象、时期或指标区别；不能只写宽泛类别或数量代替具体结果。
- 分组按主题实际内容确定；内容较少时可直接列名。直接列名且有综合结果时，先介绍综合结果及其分类，再介绍分项；分组介绍时按内容关系安排顺序。
- 有关系树时，完整结果名称和具体关系在树中展开，摘要不逐名重复；没有关系树时，摘要本身须让读者识别每个结果。

- 结果关系交给下面的关系树；具体定义、适用条件、单位、得分方向及赋值和计算方法写在对应变量的 Criteria；跨变量或整个主题的使用限制写在小book。
- 摘要只保留识别不同结果所需的对象、时期或指标词，不展开上述解释。
- 是否展示关系树按下方使用条件判断；Criteria仍须独立讲清变量的含义和取值方法。

**格式要求**：

- 二级标题用“摘要导读”。
- 摘要文字写成一个自然段，不拆成表格或逐行列表。
- 需要关系树时，将树放在该段之后。
- 分组写法：`本主题定义 **数量** 个变量：**共同维度**（①具体结果、②具体结果）；**另一维度**（③具体结果）。` 编号在整个摘要内连续，便于核对变量总数；括号内也可用斜杠归纳共同表述。
- 分组名称用 `**加粗**` 标记，不另加引号。直接列出的完整结果名称用中文双引号，其中概念用 `**加粗**` 标记。
- 括号内并列结果用顿号分隔，组间用分号分隔；直接列名时用顿号，“和”或“或”前不再加顿号。
- 数量只加粗数字，不加粗量词。
- 同一概念只强调首次出现；共享的结果维度也要明确标记。

### 关系树

**目的与使用条件**

优先用关系树展示定义内容及其关系，包括组成、计算、分类和内容分组。人口学等并列结果也可按内容分组，但不能把分组画成计算关系。关系树不能帮助读者理解时，才省略。

关系树不代替定义方案或 Criteria。

**内容要求**

1. 选择结构。

同一主题默认用一棵树。主题内的内容分组放在树内分支，不各设标签。只有包含两个或更多独立、平行的主题定义时，才分别画树并设置标签。

| 要说明的关系 | 优先结构 | 内容安排 |
| --- | --- | --- |
| 同一主题包含分项、总分、分类或辅助结果 | 主题为根 | 组成、总分、辅助结果并列；分类放在对应总分下 |
| 多个并列结果按内容分组 | 主题为根 | 内容组下列出具体结果；组名不计为输出变量，不添加不存在的计算关系 |
| 一个综合结果有多层组成 | 综合结果为根 | 依次展开领域和分项；在实际计算发生的层级说明算法 |
| 少量条目合成或划分结果 | 条目 → 计算 → 结果 | 展示输入、运算和输出；分类接在对应结果下 |

多种结构都适用时，选择能完整说明关系且重复最少的一种。不为套模板增加层级。

2. 写清节点与计算关系。

- 最终结果使用已确定的名称。
- 主题根节点表示主题，不计为输出变量；综合结果根节点表示实际输出结果。
- 展开组成的具体子项，不用条目数量代替子项名称。
- 每个合成或分类结果都要说明组成和计算关系。
- 同一组分项产生多个结果时，分别说明各结果怎样得到。
- 同名领域使用不同指标时，分别写清组成。是否属于同一跨期结果，按[已定方案](01-source-plan.md#跨期结果合并)处理，不只凭名称决定。
- 需要展示中间计算量时，注明其不单独输出。摘要总数只统计最终输出变量。
- 来源有助定位时，在对应节点旁写原始变量或题号。来源名称不另作计分成分。
- 只写已确定的算法。不把占位提示或“待确认”写入正式树。

3. 每个展开的计分子项都在名称旁填写 meta，保留取值、范围或单位；具体内容按节点含义选择。

| 节点表示什么 | meta 写什么 | 示例 |
| --- | --- | --- |
| 最终定义变量 | 最终编码、范围或单位 | `（0/1）`、`（0–8 分）` |
| 中间计分项 | 计分后的范围或单位 | `（0–3 分）` |
| 原始回答或测量值 | 原始选项、范围或单位 | 回答确为是／否时写 `（是/否）`；体重写 `（kg）` |

- 节点名称、meta 和计算关系须表示同一内容。不得混用原始回答与计分结果。
- 需要提示反向计分时，在对应子项旁注明。

4. 按适用范围放置说明。

| 说明适用于哪里 | 放在哪里 |
| --- | --- |
| 整棵树的时期 | 首行标题旁；每棵树分别注明 |
| 整棵树的人群、年龄、完整性条件或得分方向 | 标题下、分支前；没有则省略 |
| 某个分支的条件、时期或来源差异 | 对应分支旁；不要扩大到整棵树 |
| 完整重编码、补值步骤、质量核查 | Criteria 或代码，不放进树 |
| 问卷进入条件和跳转 | 对应问题块，不由关系树代替 |

共同条件不作为组成子项，也不代替各计分子项的取值说明。树中只保留理解关系所需的简短条件。

**格式要求**

1. 每棵树独占一个代码围栏。起始行写成“```text 简短标签名”。
2. 标签使用实际主题或独立量表的简称。只有一棵树也写标签。
3. 树内不插空行。不同围栏之间留一行空白。
4. 时期使用半角方括号，如 `[1993-2022年]`。取值、范围和单位使用圆括号。
5. 用以下标记说明文字作用。新写或修改的树须标记最终变量和 meta；涉及组成或计算说明时使用对应标记。

| 文字作用 | 写法 |
| --- | --- |
| 最终定义变量 | `[[result:结果名称]]` |
| 组成部分或中间计分项 | `[[component:名称]]` |
| 计算关系、阈值或条件 | `[[relation:说明]]` |
| 取值、范围、单位、时期或来源 | `[[meta:说明]]`；时期示例：`[[meta:[1993-2022年]]]` |

- 不嵌套标记，不跨行标记，不写颜色或 HTML。
- 主题标题不因位于根节点就标为 result。
- 树线和箭头由生成器标记，不按缩进推断节点身份。
- 用半角空格保留缩进，按可见字符的显示宽度对齐，不用 Tab 或字符个数估算。
- 右侧汇合时，上下转角和中间连接点必须在同一竖列。

网站负责以下显示。根节点为第一级，第一层分支为第二级。

| 对象 | 颜色 | 大小或行距 |
| --- | --- | --- |
| 普通文字 | 前两级正文色；第三级起辅助灰 | 前两级基准字号；第三级起为基准的 0.85 倍 |
| 最终变量名称 | 各层均为数据库主题色，优先于深层变浅 | 随所在行正文字号 |
| meta | 各层均为辅助灰 | 所在行正文字号的 0.85 倍 |
| 树线 | 各层均为正文色 | 第二级主干为基准字号；第三级及更深的分支和延续竖线为基准的 0.85 倍 |
| 文字中的箭头 | 各层均为正文色 | 随所在行正文字号 |
| 行距 | — | 前两级基准行距；第三级起为基准的 0.85 倍 |

- 更深层不逐层累乘字号或行距，也不继续变浅。
- 外围主干按自身层级显示，不随所在行缩小。缩进和连接位置保持不变。
- 网站须核对实际行高，避免树线或 meta 撑大行距。
- 标签复用问卷的左侧时期标签，不用顶部话题标签。树内保留标题和必要说明。
- 未修改的旧树没有标签或语义标记时，仍可按原样显示；不将此兼容方式作为新稿模板。

**模板与实例**：[查看关系树模板](../../../templates/reader-copy.md#关系树模板)。


## 定义依据：先说明标准，再说明本次采用什么

二级标题用“定义依据”，放在摘要导读之后、问卷之前。

本节优先用能清楚表达信息的图表，不限于多套方案比较。并列的依据、选择或方案差异用表格；组成、依赖或分支关系用简洁的关系图。图表不能更清楚表达时再用纯文本，必要解释可紧跟图表。图表已说明的内容不再用段落重复；不为使用图表补造方案或理由。

| 情况 | 写什么 |
| --- | --- |
| 直接保留原始事实或简单计算，没有标准选择问题 | 可省略本节 |
| 有公认且适用的统一标准 | 写标准名称、来源、版本、适用人群、组成及计分或判定方法，再说明本次时期和数据如何对应；不为凑比较罗列其他方案 |
| 只有一套可用依据，但不足以称为统一标准 | 直接说明内容、适用性和采用理由；不凑比较，也不称其为公认统一标准 |
| 多套实际可比方案在成分、计分或阈值等方面存在实质差异 | 先用一小段交代必要概念来源，再用简短对比表说明主要做法和关键差异 |

只有一套依据时，也可用“注意事项｜详情/依据｜本次处理”整理；每行只写一个事项，用短语作行名。详情/依据只保留影响本次选择的事实或文献做法；没有需要填写的内容时写“-”，不把原始数据的做法冒充本次选择的依据。处理列写采用什么及必要条件，不重复 Criteria 的具体算法或实现代码。
比较表列出方案与来源、主要计分方法、影响选择的关键差异。
只有人群、时期、题项或缺失处理影响本次选择时，才将其列入表格，不要求每行穷举。
需要比较但原文未报告的内容如实说明，不能补猜。

说明本次采用的定义；有比较时，先讲清差异，再说明选择。可放在表格的“本次处理”列或表后的必要说明中，不要求另写重复段落：

1. 写明采用哪套方案，或从哪些方案采用哪些规则。
2. 选择或调整的理由紧跟对应选择，说明实际收益和代价。
3. 说明数据限制导致的替代、项目自行确定的处理，以及适用范围。
4. 替换项目、改变阈值或另定缺失处理时，明确列出改动；不能声称完全采用原标准。

依据和选择按[通用表达](#通用表达)书写，并保留以下信息：

- 采用资料中的建议时，写清哪份资料建议什么、为什么这样建议，以及本次采用什么；不省略来源，写成项目自行推导的结论。
- 本项目另作的选择单独说明，不与资料原有建议混写。
- 同一处理只适用于部分时期或对象时，在对应说明中讲清关键区别，不让读者从各期问卷或变量条件中自行拼出原因。
- 条件和例外跟随对应做法，不为缩短句子省略，也不重复展开无关流程。

不能用“文献权威”“感觉更好”代替选择理由。
不能只写“参考多篇文献”就直接给出算法，也不能把拼接后的方案称为原文标准。

| 信息 | 保存位置 |
| --- | --- |
| 方案差异、最终取舍及对应理由 | 本节 |
| 共同适用范围和局限 | 本节集中说明一次 |
| 逐变量完整公式、阈值、边界及缺失处理 | Criteria；与本节一致 |
| 已核实的比较来源 | 比较表就近标注 |
| 原文疑点的具体证据、具体方法出处 | 参考资料说明；不重复整张比较表 |

本节规定正文内容和位置。
新结构的读取、生成和显示兼容检查按第5步执行；文案检查通过不等于成品正确显示。

**模板与实例**：[定义依据](../../../templates/reader-copy.md#定义依据)。

## 4. 问卷：调查实际问了什么

**目的**：让读者看到定义所依据的实际问题和提问程序。

**何时展示**：先看本次定义怎样得到。

| 情况 | 处理 |
| --- | --- |
| 直接采用已发布性别、年龄、官方分类，或按家庭人数等于 1 判断独居 | 通常在定义逻辑说明来源和取值即可，不展示问卷 |
| 需结合前置回答、跳题或多题关系判定结果 | 展示相关题目及理解它必需的条件 |
| 原题含义会影响结果解释 | 展示消除关键歧义所需的题目及条件 |
| 混合主题 | 按题组分别决定 |
| 全部题组都不需要展示 | 省略整个问卷部分，不写省略说明占位 |

按题组决定是否展示。展示题组时，保留本主题定义所用的相关原题，以及理解提问过程所需的条件和跳转。不能仅因结果直接取值或 Criteria 已有说明，就省略原题。
同一原题对应多个数据字段时，合并展示原题并列明字段，不重复列题。跳转到本主题内的相关题目时，应能在本期题组中找到该题；跳出本主题时说明去向，不为此抄入无关模块。

研究时仍须核实必要问卷和官方材料，并在探索记录保留证据；不能因正文省略而删除研究证据。

**内容要求**：

1. **题组分组**
   - 每个题组对应一个话题标签，组内设置时期标签。只有一个题组时也显示这两层标签。
   - 根据题目之间的联系划分题组。有跳题、前后依赖，或围绕同一内容连续追问的题目，放在同一题组内；题目较多时用内部小标题分块。没有明显联系的题目，即使属于同一个宽泛概念，也可分别成组。问卷中位置相邻，不代表必须合组。
   - 构成树表达结果关系，问卷题组表达怎样提问，二者不必逐层对应。
   - 内部小标题只用于分块，不另算题组。
   - 题组名称准确概括本组内容，优先沿用已有名称；不按每个计算结果或每道题重复建块。

2. **时期分组**
   - 先根据已核实证据比较题义、选项含义、适用人群、回顾期和提问路径，再确定时期标签；这些相同时合并时期，实质变化时另列。展示文字相同不能代替这项比较。
   - 只有题号或编码写法不同、含义和路径不变时，说明对应关系即可。
   - 一个成分发生变化，不要求其他成分一起拆分。
   - 不在整篇前面集中共同题、后面统一补各成分的变化题。

3. **问卷设计／问卷设计变化**
   - 首个时期组介绍调查对象、提问内容和顺序。
   - 后续时期组先说明相较哪个时期、改变了什么，再补充理解本期所需的设计信息。
   - 每个时期标签保留必要的完整题干、选项和提问路径，不让读者切换标签寻找。进入条件是否重复展示，按下方“进入条件与跳转”处理。
   - 不同题组之间的区别，不写成跨期设计变化。

4. **原始问题**
   - 展示完整中文题干、选项、单位及必要提问说明，包括影响进入条件的上游题和相关跳转。
   - 共用的引导语或访员说明放在本期设计说明中一次展示；只适用于部分题时，注明适用题目。各题保留自身题干和特有说明，不反复附上整组引导，也不遗漏改变题义或作答方式的限定。证据中的题干与说明分开登记，见[文案程序操作](../scoped-tasks.md#copy-operations)。
   - 已有清楚题组时，不为凑层级重复分块。
   - 共同选项的展示位置和适用范围见下方“选项”；不同的进入条件和跳转分别保留。

**格式要求**：

标题按以下层级组织。一个题组和多个题组使用相同结构。

| 内容 | 标题层级及名称 |
| --- | --- |
| 全节 | 二级“问卷” |
| 题组 | 三级实际题组名称，每组有自己的时期标签 |
| 时期 | 四级适用时期；标签尽量简短，按下方规则表示实际包含的调查期 |
| 设计说明 | 五级；同一题组首次用“问卷设计”，跨期变化另列时用“问卷设计变化” |
| 不设内部小标题的题目 | 五级原问卷标识 |
| 需要内部小标题时 | 五级内容名称，其下题目用六级原问卷标识 |

不机械复制构成树的领域、成分和分项层级。

时期标签：

- 连续调查波次，或按固定间隔连续开展且均已核实的调查年份，使用简短起止范围，例如 `Wave 1–3`、`2004–2022 年`。年份范围表示其中的调查期，不表示每年都有调查。
- 中间缺期或间隔不规则时，列明实际时期，也可组合范围与单期，例如 `2004–2010、2014 年`。不能为缩短标签而包含未核实或不适用的时期。
- 文案不手动插入换行；长标签由网站自动换行。逐期变量对应仍在题目旁保留，不因缩短标签而删减。

题目标题与正文：

- 原问卷标注了变量名时，优先用该变量名作标题。
- 原问卷只有数字题号时，保留题号，并注明已核实的对应数据变量名。
- 跨期标识不同，在题目旁说明对应时期与关系，不编造或替换标识。
- 题号与数据变量的对应信息单独写一行“对应数据变量：时期及变量名”。它属于备注，紧跟题干、放在选项之前；生成时使用已有的小字号说明样式，不并入题干，也不移到选项之后。对应关系与题目标题相同且没有补充信息时，不重复写。适用对象和跳题条件仍按下文分别展示，不混入这行备注。
- 题干不加引号；设计说明中概括的问题用中文双引号。
- 已符合[题意概括的证据条件](../evidence-and-literature.md#questionnaire-evidence)、无法取得完整原题时，在设计说明中分别写“题意概括：”和“未取得完整原题的原因：”，与证据记录一致。不编造题号或选项；必要事实未核实不能仅靠这段说明继续。

选项：

- 用短横线列出，保留原始编码和标签。
- 先按上方展示范围确定本题组、本时期需要展示的问题，再比较这些问题的选项。
- 所有这些问题的选项编码和含义完全相同时，第一题完整展开，并说明其余题目共用这些选项。不跨时期标签省略必要选项。
- 共用选项的后续题目有跳转时，只列出触发跳转的选项，紧跟去向；其余选项省略。例如：`- 1 没有困难 → 跳至 DB004。`
- 选项不完全相同时，各题分别展开。不为共用选项删去必要问题或重新拆组。
- 连续题号可写：`DB001–DB015 的选项设置相同，后续题目仅列有跳转的选项。`；不连续时列明本题组其余题号及所引用的第一题。
- 编码写法分期变化时，用 `原问卷选项编码（适用时期）：编码=标签；编码=标签。` 集中说明，题块只列共同标签。
- 导出后的解码值另作说明。

进入条件与跳转：

| 情况 | 写法及位置 |
| --- | --- |
| 前文跳题已清楚交代进入条件 | 后续题目下不重复写该条件 |
| 尚未交代的必要进入限制 | 用“适用对象：”说明；没有则省略 |
| 需要补充的进入条件由多题共同决定 | 写全各题回答及“同时满足”“满足任一”等组合关系 |
| 只有题号不足以说明适用对象 | 补充题义 |
| 某选项触发实际跳转 | 紧跟触发选项写 `→ 跳至 题号` |
| 跳转无法归入某个选项 | 在实际判断位置写“跳题说明：”，说明触发条件和去向 |
| 整组作答后才判断 | 在该组末题后写触发条件、组合关系和去向，不提前挂到首题 |
| 不再返回本主题 | 写 `→ 结束该主题` |
| 正常顺序作答 | 不写跳转提示；只有实际跳过题目、转入其他部分或结束题组时，才标明去向 |

通常写清触发条件和去向即可。跳过哪些题会影响结果理解时，再说明这层影响；具体赋值或补值方法放在 Criteria。

同一题组有多条条件分支、逐题文字难以讲清时，在对应时期的相关题目后补简短分支流程图。
图中标明判定题、回答和去向，使用 `text` 代码围栏。
图不能代替完整题干、选项或跳题说明。

## 5. Criteria：每个变量怎样得到

**目的**：让读者理解每个变量，并能据此判断一条记录该取什么值。

- **内容要求**：每个最终变量填写一组，名称与方案一致；先写组成变量，再写综合变量。
- 赋值、补值及计算条件放在相关变量的“定义逻辑”中，不在 Criteria 开头另放共同处理段落，也不用“符合共同条件”等引用代替实际条件。

| 栏目 | 内容 |
| --- | --- |
| 定义 | 用一句话说明变量表示什么，带上必要的对象、回顾期或单位 |
| 定义逻辑 | 说明所用信息、如何得到取值及必要特殊处理，具体写法见下方 |
| 分类 | 列出最终变量的有效、非缺失取值的编码与含义。NA 不列为分类。数值变量说明类型和单位。使用方案确定的类别，不拿原问卷编号替代结果编码；实际分布留在QA |
| 注意点 | 写使用时必要的换算依据、时期差异或比较限制，不重复计算步骤；没有就省略 |

定义逻辑把所用信息和取值方法连着写，特殊处理接在后面；只写实际涉及的内容，不另拆固定栏目：

1. **连着说明所用信息和取值方法。** 按实际处理选择写法：

   | 实际处理 | 写什么 |
   | --- | --- |
   | 原有含义、分类或数值不变 | 说明保留什么 |
   | 重新分类 | 写清哪些回答归入哪类 |
   | 换算或合成 | 写清计算方法、单位及必要权重 |
   | 只统一代码或标签 | 说明保留的含义；具体取值放“分类”，不重复整套对应 |
   | 使用已定义变量 | 直接接着计算，不重复该变量的生成过程 |

2. **范围说明放在对应方法旁。**
   - 涉及不同对象、时期或来源时，写清适用范围及必要选用顺序。正文可归纳跨期来源，逐期完整对应保留在来源记录中。
   - 跨期来源优先用括号内的紧凑文本说明。变量名无规律时，注明“变量名无规律”，列出实际名称；变量名有规律时，注明“变量名有规律”，合并共同前缀或后缀，用范围、分段等方式灵活简写。
   - 时期和简写范围依据已核实来源确定。突出实际差异，不为重复对应关系逐年铺表。
   - 同一变量保留跨期口径差异时，定义概括共同概念并点明差异，定义逻辑分别说明各期取值，注意点说明比较限制。是否合并按[跨期结果合并](01-source-plan.md#跨期结果合并)，不在写作时自行拆分。
   - 不用“按当期题义对应”“依口径处理”代替具体说明。

3. **特殊处理接在后面，写清条件和结果。**
   - 涉及补值、缺项计算或折算时，直接写“满足……时，本变量记为／按……计算”。
   - 多题共同触发时，写全回答及组合关系。
   - 必要时区分不能这样处理的情况。
   - 普通未回答且未另作处理，不专门补写“保留缺失”。

所有条件都来自已确定方案，原始回答用真实选项。调查提问流程放问卷；使用限制放注意点；防报错的程序细节留在代码。一句能说清就写一句，不为完整形式增加背景或步骤。

**格式要求**：

- 二级标题用“Criteria”；三级标题用实际变量名；四级标题依次为“定义”“定义逻辑”“分类”“注意点”。
- 变量名及代码格式见[通用格式](#通用格式)。
- 定义逻辑有多项时用①②③；分类用短横线，取值、编码及类别用方括号。
- 逐项比较实际差异更清楚时，可在栏目内用 Markdown 表格；必要处理仍用短句写清。生成器负责呈现真实表格，不将表格行作为普通段落输出。
- 没有注意点时删除整个栏目。

## 6. 小book：跨变量或整个主题的使用限制

**内容要求**：

按以下顺序选择内容；没有需要补充的事实时不增加条目。

1. 先说明记录单位和调查设计：一行代表什么，不同时期是否追踪同一批人。人—年长格式说明每行是一个人在某年的记录；系列横断面调查说明各年分别抽样。
2. 再说明本次多个结果共同使用时需要知道的具体差异。写清涉及的结果、时期或对象，差异是什么，以及会怎样影响理解、比较或汇总。不能只写“影响可比性”而让读者自行猜测。

直接说明交付结果，不延伸出无关的去重或统计建议。
- 只影响单个变量的提醒放在该变量的“注意点”；计算或缺失处理规则放在相关变量的“定义逻辑”。

**表达要求**：

- 每条先用一句短句点明读者需要知道的事实，再解释必要条件及其对结果使用的影响。首句不重复其他条目已讲清的要点。
- 一条围绕一个要点，句子按[通用表达](#通用表达)书写。
- 本次确实作了处理，且处理结果影响读者使用时，再说明处理结果。文件保存、程序操作和执行记录不放入小book；不能因此省略改变样本纳入范围或结果可比性的实际处理。

- 不泛泛介绍与交付结果无关的数据库背景，不设想可能的问题或补充通用分析常识。
- 例如，“调查样本会变化”“名册有记录不等于参加访谈”，只有查清与本次结果的具体关系时才写，不能代替尚未查清的事实；但不能因此删掉必要的记录单位、长宽格式和纵向或横断面设计说明。
- 没有需要补充的信息就省略，不为了凑提示另找问题。

同一使用限制已在前文或其他条目讲清，且没有需要补充的共同使用影响时，不再重复。确需补充时，只写新增的事实及影响，不换个说法重述已有结论。不汇总各变量的注意点，不搬入探索过程或 QA 计数。只写实际需要提醒的事项，不凑类型或数量。

**格式要求**：

- 二级标题为“小book提示”。
- 每条一段，条目之间空一行。生成器按顺序显示 `1. `、`2. `，只有一条也编号；文案已有编号时，生成器先识别编号，再统一显示。
- 首句以中文句号结束，不加粗；生成器将首句显示为数据库主题色，后面的解释使用正文色。
- 编号在左，换行后的文字与该条正文起点对齐，不与编号对齐；颜色与缩进由生成器统一处理，文案不手写样式。
- 没有需要单独提醒的事项时，正文写固定句“本主题没有需要单独提示的主题级边界”，生成器会省略卡片。

## 7. 参考资料说明

**目的**：说明采用的方法或解释限制有什么依据，哪些是本项目另作的选择。

- **内容要求**：没有实际使用的方法资料时省略本节，不为填满栏目补文献。
- 只列实际支持公式、计分、分类、阈值或解释限制的已核实材料。
- 每条说明材料讲了什么、支持本主题哪部分；必要时说明它没有规定、由本项目决定的处理。
- 普通应用文章留在探索记录；已在问卷展示的调查事实不再重复列作方法文献。
- 检索失败、访问过程和检查结论留在探索或执行记录。本节只说明实际采用的资料及其用途。

**格式要求**：二级标题“参考资料说明”。使用`> 1. `逐条独占一行，条目之间不空行。材料名链接到已核实地址；没有链接时给版本和页码，不编造地址。
