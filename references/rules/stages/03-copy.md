# 3. 纯文案

## 本步执行与验收

- 输入：已确定的定义方案、问卷证据、当前 raw 事实和变更范围
- 另读：[文案模板](../../../templates/reader-copy.md)、涉及引用时读 [证据与文献](../evidence-and-literature.md)
- 执行：先完成文案.md，再按最终阅读顺序通读；定义变化先完成既有影响记录，之后才交 R 和生成
- 交付：文案.md、已处理的变更影响记录
- 程序检查：check_reader_copy.py --copy <文案> --record <来源记录> 检查变量、顺序和栏目；生成阶段再比较实际文字
- 模型判断：摘要是否明确说出结果组成；Criteria 是否解释完整判定；每个提示是否有必要，读者能否复述
- 未通过：修改文案或回到未决方案；不先生成再补内容

## 仅修文案时

只读取本文件、文案模板、当前完整文案，以及解释本次事实所需的已验收方案/代码片段。无需全文读取公开 R 规范、下载流程、网站操作或另一个数据库。定义方案和 R 未变时，保留现有来源与代码复核；进入生成前用 review-check 确认其仍适用。只有既有证明缺失或相应输入改变才补该步复核，不自动重开来源探索。

每次返修都记录现有影响表中的实际修改和未变部分；纯表达修改不写成对象、变量集合或计算规则变化。首次预检与首次 R 复核的要求不等于每次改字都重做一次。

## 原始问卷输入

没有原始问卷题目的来源，不展示原始问题，也不创建空的“原始问卷”“问卷设计”或时期题块。整个主题都没有原题时，文案.md 直接省略“原始问卷”章节，正式 R 不传入问卷展示内容；程序已有这一可选路径，无需伪造题号或放宽完整题文检查。混合来源主题只展示实际存在并已核实的题目，血检等非问卷来源不凑题块。必要的测量与方法依据放在现有摘要、Criteria 或参考资料说明中，不冒充问卷。

将 [问卷文案模板](../../../templates/questionnaire-copy.md) 的“原始问卷”章节放入文案.md，按已核实时期和题目替换例子。每个时期标题下先写设计说明，题号标题下写完整题文、必要适用对象、选项及其跳转。无额外流程说明时省略“跳题说明”，不为凑栏目添加题后解释。

read_definition_copy() 同时返回 summary_selection；正式 R 将它直接传给生成器，不再另写一套问卷文字。生成前后都逐期比较全部可见内容。旧主题只改摘要、Criteria 等其它文案且问卷内容未变时，可以继续使用 R 中既有问卷并重新生成，不为本次返修强制迁移。新建主题或本次修改问卷展示时，将该主题问卷迁入文案.md，并移除 R 中对应的重复文字。

通过本步才交接给下一步；一次命令或点击不是一个独立验收环节。只读复核者接收本步稳定输入、对应标准及具体问题，不接收整个历史对话。

### 0.1 定义变更影响门

新主题，或既有主题新增、删除、重命名分析变量，改变调查对象、周期、问法、计算组成或缺失处理时，必须在编写正式 R 前建立 `definition_change_impact.json`。先运行 `check_definition_readability.py init-impact` 生成检查表，再用大白话填写本次改变了什么、会影响哪些读者材料和数据成果。人类可读填写说明见 [change-impact.md](../../../templates/change-impact.md)。

检查表不是完成后的变更摘要。每个新增或改变的问卷题组都必须在正式编码前记录：调查时期、询问对象、官方材料位置、核对过的代表性原题、这道题怎样进入定义，以及原题写在正式成果目录 `文案.md` 的什么位置。官方材料无法核到逐字原题时，只能填写大白话概括和无法逐字引用的原因，不得放进引号冒充原题。

检查表同时覆盖标题与摘要、问卷原题、定义表与变量顺序、全部 `Criteria`、小book提示、公开 R、mapping/codebook、定义卡与图表。未受影响的部分也要写明为什么不受影响，不能留空。检查表仍有待处理项，或核对过的原题没有实际出现在纯文字稿时，不得进入正式生成。

`check_definition_readability.py check` 必须验证当前检查表、纯文字稿、作者全文审核和四份正式成果属于同一版本。网站同步任务开始时还必须运行 `verify-ready`；它只复核现有发布许可，不生成或修补任何审核文件。复核失败时不得绕过。同步完成后进入用户检查阶段，只有用户确认后才算完成。

### 1.3 三类内容不要混写

- **摘要导读、小book提示、`Criteria` 和参考资料说明**先写纯文字，详细要求见第 5、6 节。
- **公开 R 注释**跟着对应代码写，详细要求见 [公开 R](04-public-r.md)。
- **展示样式**最后添加，不能参与写作。

`文案.md` 至少按 `## 摘要导读`、`## Criteria`、`## 小book提示`、`## 参考资料说明` 分成四部分；`Criteria` 下再按最终定义变量逐项列出完整文字。没有小book提示时，在文案中写明“本主题没有需要单独提示的主题级边界”，正式笔记中省略提示卡。参考资料说明必须逐条写清材料支持的事实和不支持的项目处理，不能等生成笔记后再补。

如果本次只返修其中一类内容，开始前必须写清允许改什么、禁止改什么。不得因为这些内容最后出现在同一篇笔记中，就顺手改动其它文字、代码、变量或样式。

## 4. 用户文字共同原则

本节是定义笔记、公开 R 和下游宣传材料共同使用的事实与语言底线，不是要求各载体复制同一段文案。定义笔记、公开 R、公众号 SVG、富文本和其它宣传材料分别按自己的读者任务组织内容；任何载体都不能改变已确认事实，也不能反向产生新的定义规则。

1. **先从已经确认的事实和定义方案生成初稿。**初稿依据实际 raw 取值与标签、正式 codebook、官方材料、已经确认的定义方案和明确裁决。旧 `Criteria`、旧笔记、旧 HTML、历史脚本和既有成品只能在初稿完成后查漏和回归，不作为事实权威或措辞底稿；最终句子可以相同，不为制造差异而改写。
2. **每个事实都有依据。**数字、编码、阈值、权重、区间、来源、周期和优先级不能根据上下文补全。
3. **只写有独立解释价值的信息。**删除后不影响读者理解变量含义、赋值、比较或使用边界的句子不进入用户文本。
4. **忠实于判定口径，不照译代码。**允许调整叙述顺序、合并重复分支、使用公式并直接写转换结果；不复述函数名、中间对象、防御性判断和程序语法。
5. **普通缺失默认省略。**只说明特殊编码、条件性缺失、完整性门槛、部分项目缺失或缺失传播等会改变解释或分析选择的情况。
6. **同一栏目不重复同一事实。**同一事实确实需要跨栏目出现时，每个位置必须承担不同职责和信息粒度，例如摘要只概括来源组成，`Criteria` 再说明具体赋值；不能只是换一种说法重复。
7. **通俗易懂优先于简洁。**先把对象、依据、前后关系和必要例子讲清楚，再删真正重复的文字；不能为了短而省略主语、条件、因果或中间关系。
8. **不使用机械语言指标。**禁词命中、句子重合率、改写率和“旧句复用为零”不能证明语言质量；机器只核对事实、结构和同步。

写入前依次判断：有无正式依据；有无独立解释价值；是否放在正确栏目；普通读者是否无需补背景就能读懂；最后才判断能否更短。

### 4.1 标题、变量名与显示标签

- 笔记标题准确概括本主题实际定义的内容，不能大于分析变量的真实范围。只定义耐用品时不写成“家庭资产”，只定义一种服务时不写成整个上位主题。研究概念在探索后缩窄或拆分时，标题必须在正式生成前同步调整。
- 中文标题优先使用普通读者和相关研究都能理解的概念；英文标题使用含义相同的常见研究表达，不逐字翻译 raw label，也不把处理步骤、数据库模块或内部状态写进标题。
- 标题保留区分研究对象、方向、时间或范围所必需的信息，但不把所有组成变量堆成一串。读者只看标题时，应当能够大致判断本主题定义了什么、没有定义什么。
- 分析变量名和 `analysis_codebook$Label` 是定义结果的统一身份。定义表、`Criteria`、定义卡、图表标题和 defined variable 展示必须与它们语义一致；可以为可读性调整句式，不能改变对象、方向、回顾期、单位或分类含义。
- source variable 的 `Easy.label` 说明原始题目本身，不能因为它最终参与某个分析变量，就改写成分析变量的含义。defined variable 的显示标签来自对应分析变量的 Label。两类标签不得混用。
- 组分概览与组分详情按真实研究概念显式分组，不依赖变量名或 Label 的字符串碰运气匹配。分组名称使用读者能理解的业务概念，不使用内部对象名、循环名或处理阶段名。
- 任何变量重命名或 Label 修改后，必须一次核对并同步：`analysis_vars`、`analysis_db`、`analysis_codebook`、mapping、定义表、全部 `Criteria`、Easy.label、组分概览与详情、定义卡、图表标题，以及公开 R 中对应的章节标题和注释。发现旧名残留或含义错配时不得发布。
- 全文审核必须把所有读者可见的标签和图表文字当作正文阅读，包括 source variable 的 Easy.label、analysis variable 的 Label、组分详情、定义卡、坐标轴和图例。变量代码名保持原样；解释性文字若仍是维护者英文、内部缩写或读者无法直接理解的短句，应改成说明对象、题义或结果的自然语言。

### 4.2 通俗表达的具体标准

笔记面向没有数据库、R 语言或问卷设计背景的普通读者。所谓“通俗易懂”不是删掉事实，而是把事实按照日常理解顺序说完整。每段先回答一个具体问题，例如“调查问了谁”“问了什么”“为什么不能直接合并”“最后怎样处理”，不能只堆抽象结论。

- 使用完整、自然的主谓句，明确谁做了什么、在什么条件下得到什么结果。避免省略主语后连续堆放“来源、口径、路径、边界、结构、身份、机制”等抽象名词。
- 优先使用读者熟悉的现实对象，如“受访者”“配偶”“子女”“家庭”“医疗机构”和“过去一年”。专业词确实必要时，第一次出现立即用日常语言解释，后面才可简称。
- 内部技术词不能直接充当解释。需要表达时，改成读者可以观察或使用的事实：
  - “数据层级”说明为“一行代表一个人、一个家庭，还是一名家庭成员”；
  - “回顾期”说明为“调查询问的时间范围，例如过去一个月或过去一年”；
  - “结构性缺失”说明为“受访者因前面回答而跳过这道题，并不是漏答”；
  - “来源身份变化”直接说明“谁回答、问的是什么或来自哪类问卷发生了变化”；
  - “周期边界”直接说明“哪些年份可以比较、哪些年份含义不同，以及为什么”。
- 先说业务事实，再给变量名、编码或公式。不能用一串 raw 名、裸编码或函数名开场，让读者自行推断题义。
- 一句话只承担一个主要意思。需要同时说明对象、年份变化、数量和处理结果时，拆成短句、分行或简表；不能把所有限定条件塞进一个长句。
- 只有抽象规则仍难理解时，补一个真实且必要的例子。例子用于解释规则，不重复制造另一套定义，也不能用例子替代完整规则。
- 通俗表达不能变成空话。“根据实际情况处理”“按相应规则计算”“不同年份有所变化”等句子如果没有说明具体对象、变化和处理方向，必须重写。
- 每段写完后做一次零背景复述：不看代码和上下文，普通读者能否说出这段在讲谁、发生了什么、为什么重要、最终怎样处理。不能复述时，说明对象、条件或因果仍然缺失。

### 4.3 特殊情形触发表

只在真实命中时应用，不为填满模板制造内容：

| 情形 | 必须核查 | 读者最终需要理解什么 |
| --- | --- | --- |
| 大量循环变量 | 对象、类型、方向、周期等真实维度，各组列数与总数 | 读者能看懂问卷对哪些现实对象反复提问、每次记录什么，以及为什么会形成许多原始变量。只有乘法确实帮助理解且问卷结构已经核实时才展示数量，不从变量后缀推测人数限制 |
| 跨周期问法变化 | 共同研究含义、回顾期、题目形式、记录方式、采用信息 | 读者能分清哪些内容各期相同、哪些内容发生变化，以及这些变化为什么影响定义或比较。是否使用背景段、列表或表格由内容决定，不规定固定开场 |
| 直接回答与推导混用 | 哪些周期直接回答，哪些周期由金额、次数或分项推导 | 先区分记录方式，再明确各自判定条件；不得用“直接记录”等模糊表述跳过中间逻辑 |
| 多来源优先或回填 | 主来源、补充来源、触发条件和顺序 | 读者能知道什么情况下使用哪个来源，以及后一个来源何时才会参与 |
| 跳题或筛选题 | 上游筛选、进入条件、下游空白含义、适用对象 | 明确 No 或结构性跳题何时应为 0，Yes 后信息不足何时缺失；无法区分时不擅自补 0。参与判断的筛选信息必须进入 raw、mapping 和公开代码 |
| 公式变量 | 最终公式、输入、换算、权重、完整性 | 读者能复算结果，并知道输入不足时怎样处理 |
| 汇总变量 | 构成最终结果所需的全部组成项 | 读者能看懂由哪些组成项得到结果、何时可以计算，以及组成项不足时怎样处理 |
| 不同原始题目导致最终变量冲突 | 各变量的直接来源、冲突方向、数量和是否有用户裁决 | 默认按直接来源分别生成并保留冲突，不为内部一致性改值；`定义逻辑` 写各自生成规则，只影响单个变量时由该变量的 `注意点` 说明冲突题目、数量、表现和解释影响，同时影响多个变量或整个主题时再由小book提示说明总体边界。只有用户明确要求时才写修正规则 |
| 周期缺少对应来源 | 缺少的题目或来源、实际赋值、解释边界 | 按“缺少什么 → 怎样赋值 → 能表示什么、不能表示什么”说明 |
| 来源身份或题义变化 | 实际语义、对象、项目结构与可比性 | 只影响单个变量的判定或解释时进入该变量的 `定义逻辑` 或 `注意点`；同时影响多个变量或整个主题的周期比较时进入小book提示。题义不变、仅 raw 名变化时在 `定义逻辑` 交代必要来源，不另写注意点 |

## 5. `Criteria`

### 5.1 栏目职责

- `定义`：用一句完整的话回答变量表示什么。优先写清研究对象、测量内容，以及属于变量含义的回顾期或单位；不写调查年份、raw 名、来源文件、处理过程、缺失或研究建议。
- `定义逻辑`：写真正影响结果的适用对象、判断来源、赋值、计算、优先级、补零、特殊缺失和完整性，按实际决策顺序组织。
- `分类`：只列最终编码和类别含义；连续变量默认只写“连续变量”和单位。理论最大值、观察范围和极端值进入 QA，除非范围本身属于正式定义。
- `注意点`：只写当前变量不属于赋值步骤、但影响追溯、比较或解释的事实。影响多个变量或整个主题的来源与周期边界、数据层级和重大结构问题放到小book提示，不在每个变量中重复。没有内容时省略整个栏目，不写“无”“暂无”或“不适用”。

### 5.2 写作规则

先在 `文案.md` 的 `## Criteria` 下，按最终定义变量逐项写完整。使用[纯文案模板](../../../templates/reader-copy.md)：三级标题为实际分析变量名，四级标题为本节规定的栏目；注意点仍按第 5.1 节判断是否需要。文案中只写读者会看到的文字，不写 HTML、样式或渲染函数。

在后台生成区调用 `copy <- read_definition_copy(analysis_vars)`，将返回的 `criteria`、`summary_entry`、`summary_insight_items`、`reference_lines` 传入现有渲染器。这四项从同一份 `文案.md` 读取，不在 R 中重新手写。问卷题块仍使用既有结构化组件和问卷证据核对。摘要中已有的重点可以用 `**概念**` 标记，加载器转换为既有主题色标记；文字本身保持不变。

- 普通单题直接写“题义 + 回答选项 + 赋值”。题义和判定不变、只是跨周期更换 raw 名时，统一赋值只写一次，周期与必要来源放在同一编号项。
- 同一对象、含义和回顾期跨周期保持不变时先交代共同口径，只展开真正变化的部分；判定相同的周期合并书写，不按年份机械排比。
- 多步骤定义按“适用对象 → 判定来源 → 赋值或公式 → 补零与特殊缺失 → 完整性”的实际决策顺序组织。主题事实不需要其中某一步时直接省略，不为凑齐模板制造内容。
- 下游变量只对已经定义的上游变量重新归类时，只说明分组关系，不重复上游清洗。
- 原始选项保留问卷或 raw 的真实标签；基于题目前提、结构或裁决推定的换算值在 `注意点` 说明依据和解释边界，不改写成原始选项。
- 正常数值按题目单位保留时，不写“其余非负数保留原值”等防御性条件。
- 不把 `TRUE ~ NA`、未匹配类别或程序兜底翻译成用户说明。真实存在的拒答、不知道、不适用等特殊值按其实际含义说明。
- 跳题或筛选题参与定义时，明确区分：已经确认没有发生时何时记为 0；应当继续回答但信息不足时何时保留缺失；无法区分正常跳题和漏答时不得擅自补 0。
- 公式变量按“最终公式 → 各项输入 → 单位或时间换算 → 完整性与缺失传播”说明；不能只给计算结果而省略输入条件。
- raw 名只在追溯或区分来源确有必要时放在对应业务句中或句末，不能先堆 raw 名再让读者反推题义。
- 多项规则使用 `① ② ③...`。只有当前变量后续多条判定共同依赖一个必要前提时，才在编号规则前使用公共 `criteria_context()` 渲染浅底背景块；适合放入的内容限于跨期组成变化、适用人群或容易误解的解释边界。普通变量含义、简单组成清单、具体赋值、公式、补零和缺失处理仍写在正常定义逻辑中，不使用底色强调。没有独立前提时省略背景块，不为统一外观机械添加。背景块直接讲清事实，不加“各年的来源不同”等固定开场。`分类` 使用短横线；小标题单独一行并加粗，内容保持轻量缩进。
- 变量名和代码对象使用 inline code；数据取值、编码、分类值和问卷选项使用方括号强调，不写成 inline code。
- `definition_data$Criteria` 是从定稿文案读取的渲染输入。definition HTML、笔记和其它用户材料从这里生成，不再维护第二份手写文字。

原始矛盾专项只在用户明确要求时执行，不作为每个主题的机械扫描；但在正常定义或验证中已经发现的矛盾不得忽略。发现后按以下默认规则处理：

1. 各定义变量按自己的直接原始题目分别生成，不替受访者判断哪道题正确。
2. 允许状态、金额、次数或其它分别来源的定义变量互相矛盾。例如筛选题为 No、金额题为正金额时，状态保留 0，金额保留正金额。
3. 未经用户明确裁决，不得采用筛选题优先、金额题优先、强制补 0、改缺失、删除金额、排除记录或其它内部协调规则。
4. 在过程证据中保存冲突记录，至少包含身份键、周期、涉及的原始题目与原回答、冲突方向；生成规则写入相关变量的 `定义逻辑`。只影响单个变量时，由该变量的 `注意点` 说明题目、数量、表现和解释影响；同时影响多个变量或整个主题时，再由小book提示说明总体边界。
5. 能按直接来源分别忠实生成时，报告后继续，不自动进入 `RESULT_REVIEW_REQUIRED`。只有单个定义变量自身的来源或生成规则无法确定，或存在来源不明、重复计入、多来源覆盖规则不明等实质问题时才暂停裁决。

触发专项后还要说明来源组和最终是否保留或按用户裁决修正，不把派生关系或正式覆盖误写成原始冲突。

`Criteria` 的 HTML 结构、颜色、缩进和间距由公共 helper 与固定测试维护；主题脚本只提供语义内容和结构标记，不复制 CSS 实现。

## 6. 摘要导读与小book提示

固定顺序为：**最终定义信息区 → 可选关系结构 → 原始问卷与时期分组 → 可选小book提示 → dbCodeBook 目录入口**。摘要先让读者知道最终得到什么，再按真实时期说明问卷原来怎样提问以及设计发生了什么变化。目录入口只在上述内容之后简要交代。来源与周期边界、数据层级与分析单位，以及跨变量或整个主题的重大结构问题由小book提示承担，不在首段或目录入口重复展开。摘要不再生成五列表；全部分析变量及其顺序由后面的 `Definition / Criteria / detail` 定义表展示。

摘要导读、小book提示和参考资料说明先写在 `文案.md`，读顺以后再放进主题生成源。公开 R 不走这一步，按 [公开 R](04-public-r.md) 结合代码编写。

加入样式前，逐段做一次零背景检查：

- 假定读者不了解数据库、问卷和 R。
- 读者应能说出最终定义了什么、各部分是什么关系、为什么需要这些原始变量，以及每段话为什么出现在这里。
- 遇到内部术语、突然出现的数字、前后跳跃、空话套话，或虽然简短但不能复述的句子，先改清楚。
- 没有读顺以前，不加颜色、链接、卡片或其它样式，也不运行正式渲染。
- 审核记录要写明实际发现和修改，不能只写“已通读”或 `PASS`。

文字通过以后，样式阶段只能添加语义标记，不能改句子。确实需要改字时，先回到 `文案.md` 修改并重新通读。渲染完成后，再提取摘要导读、小book、全部 `Criteria` 和参考资料的可见文字，与 `文案.md` 逐段核对；文字不同就不能发布。

### 6.1 先说明最终定义了什么

- 摘要开头先让读者知道最终定义了哪些变量、各变量表示什么，以及它们之间有什么关系。
- 摘要首段中的定义变量总数、定义结果名称和关键概念使用既有语义标记显示主题色。成组列出多个已经命名的定义结果时，每个名称分别保留中文引号并单独标记，例如“总费用”、“自付费用”和“自付比例”；多组变量共享“是否发生”“金额”“比例”等最终结果维度时，这些维度也要分别标记，不能只突出组名。主题色只作用于引号内文字，标点、连接词和解释句保持普通文字颜色。不得只高亮总数或组名，却把读者真正需要识别的结果名称埋在普通正文里；也不得把整句话全部染色。同一概念在同一自然段或同一个连续信息块中原则上只标记一次；后文继续解释时改用“这一组”“最后一项”等自然指代，或保留普通文字，不重复着色制造两个视觉重点。
- 只有一个定义变量时直接点名，不使用“等”；多个变量时完整列出，或在不遗漏关键分支的前提下概括后明确总数。
- 综合得分、指数或分层定义先说明综合定义，再完整说明全部组成变量及其关系。非综合主题先说明全部定义变量或真实业务分支。
- 开头不介绍目录、检索过程、逐年 raw、赋值细节、特殊编码、周期可比性、数据层级或重大结构问题。

### 6.2 再说明调查原来怎样提问

- 这一部分解释为什么需要这些原始变量：调查问了谁、问了什么、怎样反复记录，以及这些信息分别用于哪些定义变量。原始变量总数只需在能够准确核对时说明一次，不围绕计数组织整段文字。
- 面向读者的笔记、`Criteria` 和公开 R 统一使用“原始变量”。不得用“来源字段”“raw 字段”“来源项”等内部说法代替。只有确实讨论数据表中的列结构时才使用“字段”，并立即说明该字段具体记录什么。
- 来源简单时用自然段；内容复杂时可以按现实对象、业务分支或问卷阶段分组。选择哪种结构只看哪一种最容易让读者理解，不预设固定标签、固定段数或固定句式。
- 涉及多版问卷时，各时期分别讲清当时真实的询问对象、问题内容、继续追问的信息、跳题程序和记录方式。某一期特有的问法必须留在该期，不得写成所有年份的共同规则。
- 官方问卷能够核到原题时，直接呈现所有实际参与定义的题目，不再只挑一两个问题概括问卷流程。每道题按原问卷保留题号、中文原题、回答选项、填答单位和影响定义的跳题说明；访员提示、卡片内容或无关支路只有确实影响题义或取值时才保留。摘要的问卷结构区使用统一题块：分组标题、题号和问题顶格，题号加粗，中文原题不加引号；回答选项及跳题说明逐行缩进。回答选项独立设置为 `0.8em` 和 `#888888`；题干后的进入条件与选项后的跳题说明都独立设置为 `0.72em` 并继承正文默认深色。字号不得通过父子元素的 `em` 相乘得到。同一行同时包含回答选项与跳转信息时，两者使用同级、互不继承字号的文本元素。题号、题干、填写说明和访员说明不设置文字颜色。主题内影响定义的跳题按原问卷保留；主题出口的读者表述按下方模板处理；“填写”“记录”等提示只有原问卷确实出现时才加入选项。整个时期标签内容统一使用正文的 `0.92em`；时期内第一个分组标题不增加上方间距，后续题组标题和相邻问题之间保留轻量间距。根据变量标签或数据结构推断的题意只能写成概括，不能放进原题题块。
- 如果一个主题涉及的研究问题、问卷分支或原题数量过多，已经无法在时期标签中完整、自然地讲清楚，应在撰写 `文案.md` 之前按独立的研究问题拆成多个主题。拆分以“每个主题能够完整说明一组定义变量及其全部必要来源”为准，不设置机械的变量数或原题数门槛；不得拆散同一个定义变量，也不得把同一条定义链路分到不同主题。共同筛选题可以在相关主题中重复说明，但不能因为别处出现过就省略本主题理解定义所必需的题目。禁止用删减原题、只列题号范围、把不同对象或业务支路合成一句概括等办法控制篇幅。
- 多道原题的回答选项和跳题条件完全相同时，每道题的题号和题干仍要完整列出，但相同选项可以在这一组题目之后集中列一次，并明确哪些题共同使用；存在不同选项、不同单位或不同跳题路径的题目，差异必须紧跟对应原题，不能被合并说明掩盖。
- 原始问卷按下面的展示模板排版。方括号为占位内容；题干、选项、进入条件和跳题方向均以本期原问卷为准。需要交代进入条件时，必须写明原问卷据以判断的题号及回答，或问卷明确生成的程序变量；入口由多题共同决定时如实列出这些题。判定题未在当前题组展开时，同时简述该题识别的工作或对象，不能只列题号，也不能改写成无法追溯的对象概括。进入条件紧跟题干放在同一行的全角括号内；没有特别条件就省略，不显示“题前说明”标签。访员提示、占位符解释和来源标注不写成进入条件。

```text
**FA001** [完整原始题干]（[符合原问卷进入条件的受访者回答本题]）
  1 是 → 结束该主题
  2 否
```

本分支不再进入本主题问题时，选项后统一写 `→ 结束该主题`，不附原问卷出口题号或题目解释。主题内的条件跳转保留 `→ 跳至 [准确题号]`；普通顺序作答不逐个选项补写“继续下一题”。是否结束本主题按完整问卷路径核对，不能把暂时经过无关题目后仍返回本主题的路径写成结束；不另设“题后说明”。

笔记正文不标注“（官方流程图）”，也不集中声明跳转依据来自官方流程图。实际题号、完整路径及官方材料依据保留在内部来源证据中，用于核对，不搬入读者文案。影响题义且必须保留的访员提示或占位符解释放在该期“问卷设计”说明中，不与答题对象混写。

- 每个时期只设置一个说明块，标题统一使用“问卷设计”。说明块先客观交代本期询问哪些对象和信息、问题怎样继续追问，再另起一段说明它相较前一时期新增、取消或改变了什么；不得再把原题或程序路径各复制成一张说明卡。完整题干、选项和影响定义的跳转只在紧随其后的 `summary_questionnaire_line()` 题块中呈现一次。例外应先直接说明具体缺少或不同的题目，再解释其它问题怎样继续，避免用“除……外”把关键事实藏在从句里。第一个时期作为比较起点，应把完整提问程序讲清楚；后续时期不必重复抄写所有未改变的原题，但不能直接从“与上一期相比”开头而省略本期实际问了什么。“问卷设计”块的首段顶格，第二段及以后首行缩进；缩进由公共渲染组件统一生成，不在主题文案中手写空格。
- “问卷设计”或“问卷设计变化”的说明文字保持自然叙述，并用中文引号标出这一部分实际询问的核心问题或信息。引号内可以是简短的问题概括或信息名称，不要求照抄完整原题，也不必改写成带问号的新问句；但不能改变询问对象、时间范围、支持方向、条件和含义，也不得称为“原题”。下方按题号、题干、选项展开的结构化原始问卷题块才负责呈现核对过的原题，并且仍不加引号。一个时期同时涉及多个相对独立的对象或问题组时，可以用①②③直接标出各部分；信息较多时可以分成多个自然段。编号和分段只用于帮助读者看清内容关系，不得机械地给每句话编号，也不得把本来连续的一件事拆碎。
- 原始问卷与项目处理必须分开。时期标签只按“原始问卷题目与选项 → 原问卷跳题路径 → 发布数据怎样保存 → 问卷设计发生的变化”说明调查事实，不设置“定义处理”栏目，也不写项目的逐变量赋值。如何记为 0、1、金额或缺失，怎样计算、补零和处理例外，统一写入对应变量的 `Criteria`；不能把项目结果倒写成问卷提问方式，也不能在原题中间穿插代码判断。
- 问卷按人物、机构或项目反复提问时，说明现实中的提问过程和每次记录的信息。不能仅根据变量后缀或宽表列数推断“最多 N 人”“前 N 人”或固定顺序。原始变量数量或乘法只有在准确且确实帮助理解时才展示。
- 跨周期总数从最终采用的原始变量按完整来源身份去重得到。不同问卷版本的数量只有确认互不重叠时才能相加；否则只报告去重后的总数，不展示误导性的算式。
- 中文引号只用于正文中直接引用的问卷原题或访员说明、原始回答选项，以及确实需要与日常含义区分的概念。摘要的结构化问卷题块不加引号，使用 `summary_questionnaire_line()` 生成。问卷分组标题使用主题色加粗；回答选项使用 `0.8em` 和 `#888888`；题干后的进入条件与跳题说明均使用独立的 `0.72em` 并继承正文颜色；题号、题干、填写说明和访员说明均继承正文默认颜色。
- 来源组成、原始题目结构及其与定义变量的对应关系以完整、清楚为优先，不得为了缩短摘要而删除理解或复核所需的信息。内容较长时，将这一完整信息区标记为 `.raw-source-structure`；网站前端可以据此提供展开或收起，但笔记源文件、复制内容和导出材料必须保留全部正文。折叠属于展示层处理，不能反过来要求定义文案缩写。
- 多个年份或问卷阶段需要分别完整说明时，在 `.raw-source-structure` 内按真实年份或阶段建立 `.raw-source-period` 分组，并用 `data-label` 保存读者可见名称。笔记只负责完整内容和语义分组，不写标签按钮、隐藏样式或切换脚本；网站可以将这些分组显示为标签页。没有网站脚本、复制全文、导出或打印时，所有分组必须仍然完整存在。

### 6.3 定义表、关系结构与文献

- `Definition / Criteria / detail` 定义表必须覆盖 `analysis_codebook` 中的全部分析变量，并与 `analysis_vars`、`analysis_db` 和 `analysis_codebook` 保持相同顺序。综合得分、指数或分层定义统一按“组成变量在前、综合变量在后”的定义逻辑排列。
- 定义表、定义卡、图表和 detail 不要求逐字使用同一句话，但必须表达同一个对象、方向、回顾期、单位和分类。变量重命名后按第 4.1 节执行整套同步核对。

- 只有定义变量存在已确认的多层组成关系时，才在最终定义信息区之后增加等宽代码树；普通单层主题省略。
- 代码树只使用正式节点名称、范围和已确认公式，不新增阶段标题或解释。前导空格和树线属于结构，必须保留。
- 文献只收录直接支持公式、计分、阈值、构造方法或解释边界的原始方法、正式指南、官方技术材料或不可替代的高质量研究。只说明“有人这样用过”的普通应用论文留在过程证据。
- 官方问卷用于核对原题、选项、回顾期、询问对象和跳题程序。上述内容已经在“原始问卷与时期分组”中直接展示时，不再把同一份问卷列入文献区重复说明；某期没有继续收集某类问题，也在对应时期标签或必要的小book提示中讲清楚，不另列一条问卷引用。
- 官方材料只有在问卷题目之外还明确规定了派生变量、公式、阈值、计分或方法边界时，才作为方法依据进入文献区，并且只说明它额外支持的那部分。原题展示不能代替方法文献，方法文献也不能代替原始问卷事实。
- 笔记引用只能来自候选阶段已经同步记录的官方材料或文献核对；不能在笔记完成后为了装饰或补格式临时寻找引用。正文实际采用而探索记录未登记的证据，必须先回到探索记录补做真实核对，不能根据成品反向编造调研过程。
- 每条引用用大白话依次说明：这份材料研究或规定了什么 → 它具体支持本主题的哪一部分 → 哪些来源连接、跨期处理、缺失处理或公式仍是本项目自己的决定。材料没有报告的内容直接说明“该材料没有说明”，不得写成含糊的“提供参考”。
- 引用放在完整定义表格之后、`## 材料`之前；与表格空一行，多条之间不留空行。每条使用 `> 1、文献内容`，标题链接到正式来源。

### 6.4 小book提示

- 小book提示只说明同时影响多个定义变量或整个主题理解与使用的宏观边界。只有命中以下至少一类且值得普通读者了解时才生成；没有则省略整张卡：
  1. **来源与周期边界**：不同周期的询问对象、回顾期、问卷范围或来源身份发生整体变化，影响跨期比较或解释。
  2. **数据层级与分析单位**：家庭、个人、家庭成员、社区或其它层级之间的对应关系会影响样本量、重复记录、汇总或研究单位。
  3. **跨变量或整个主题的重大结构问题**：同一问卷结构、样本覆盖、原始矛盾或其它事实同时影响多个变量，不能靠阅读单个变量的 `Criteria` 完整理解。
- 同一张卡按实际复杂点使用 `① ② ③...` 和普通换行；只有一点时不强制编号。
- 面向普通读者时通常控制在 2 至 4 个短段落，每段只承担一个主题级边界。超过这一范围时，先把重复的时期说明、单变量处理和 QA 计数移回时期标签、对应 `Criteria` 或过程报告；只有这些信息确实共同改变整个主题的理解与使用时才继续保留。
- 小book标题后的第一段不缩进；连续叙述从第二段开始首行缩进 `2em`。以 `① ② ③...` 或数字序号开头的分项本身不缩进。段落结构和缩进由公共生成工具统一写入笔记，不由网站补做，也不在 `文案.md` 中手写空格。
- 每点直接说明“需要注意什么 → 真实例子 → 为什么影响本次定义”，按需补充已经确认的处理结果。不要用“上一波次预载信息：”“跨年份变量演变：”等类别标签机械开头。
- 提示卡直接写读者需要理解的调查对象、记录范围和使用影响。上游主题或变量只有在确实参与当前主题的适用对象判断、结果保留或解释边界时才写入，并当场说明它在当前主题中起什么作用；与结果解释无关的主题编号、核对数量和跨主题一致性检查留在过程证据。
- 同一主题级边界只设一个主要说明位置。已经在小book提示中完整说明的空白含义、适用对象或跨期比较边界，摘要导读和来源入口不再重复；摘要只介绍定义结果与关系，来源入口只说明去哪里查看原始来源。
- 整张卡必须形成一条能连续读懂的说明链：先交代主题级边界或结构事实，再用真实周期、对象、记录方式或数据层级说明具体表现，最后说明它怎样影响比较、汇总或解释；只有本次确实作出处理时才补充处理结果。编号用于分开不同复杂点，不把因果相连的事实硬拆成互不衔接的孤立条目，也不为追求条数而机械合并。
- 只影响单个变量的特殊编码、补零、缺失、异常、冲突或适用条件放在该变量的 `Criteria`；不得为了填充提示卡重复搬运。一个问题即使同时影响同一业务分支中的多个状态或金额变量，只要没有跨越不同定义分支、也不改变整个主题的比较或使用方式，仍优先在这一组变量的 `Criteria` 中说明，不能仅凭“影响多个变量”放进小book。问卷按现实对象重复展开但只用于解释来源数量时，留在摘要的来源组成；只有这种结构进一步影响多个定义分支或整个主题的解释与使用时，才进入小book提示。
- 生成提示卡前，逐句与时期说明和全部 `Criteria` 对照。如果提示中的事实已在这些位置完整讲清，而且没有新增主题级解释边界，就在 `文案.md` 写明“本主题没有需要单独提示的主题级边界”，正式笔记省略整张卡。不得仅为保留版式而把已有内容重新汇总一遍。
- 变量名和代码身份在生成源中使用成对反引号，由公共 helper 转为 inline code；主题脚本不手写 `<code>`。
- 提示卡不是 `Criteria` 的压缩版，不展开完整赋值流程，也不添加难易评价。

### 6.5 语义标记与载体

- 问卷题块沿用 `summary_questionnaire_line()` 生成；展示以第 6.2 节模板为准。既有调用保持兼容，不因本次展示调整要求历史主题改写生成代码。
- `文案.md` 直接写完整题干、选项、进入条件和逐项跳转，最终笔记保留相同的文字与顺序。进入条件紧跟题干并用全角括号包住；最终题块将进入条件与跳题说明显示为同一档正文深色小字，选项显示为稍大的浅灰文字。三者各自设置字号，不使用嵌套字号。排版在已有全文审核中对照模板检查，不要求额外的位置标记或专用检查报告。
- `dbCodeBook` 保持正文样式；完整目录标记为目录；数量只标记数字；需要与日常含义区分的定义概念保留中文引号并只标记引号内文字；变量名使用 inline code。“问卷设计”或“问卷设计变化”说明中的引号内文字使用 `.summary-period-question` 与 `data-summary-period-question="true"` 标记，并显示主题色；引号和说明中的其它文字保持正文颜色。核对过的问卷原题使用 `.summary-question` 与 `data-summary-question="true"` 单独标记；题干后的进入条件使用 `.summary-question-condition[data-summary-question-condition="true"]`，或结构化题块中的 `[data-summary-question-detail-role="instruction"][data-summary-question-position="before"]` 标记，独立设置 `font-size:0.72em` 并继承正文颜色；结构化题块另用 `.summary-questionnaire-line` 标记并缩小一号。回答选项用 `data-summary-question-option="true"` 或 `data-summary-question-detail-role="option"` 标记，独立设置 `font-size:0.8em;color:#888888`；选项后的跳题说明用 `data-summary-question-instruction="true"` 标记，独立设置 `font-size:0.72em` 并继承正文颜色。承载同一选项和跳题说明的外层只负责换行与缩进，不设置字号。位于选项后方的其它填写说明和访员说明不设置颜色。问卷分组标题使用主题色，整段解释不额外着色。
- 中文数字与量词之间留一个半角空格，例如 `12 个`、`2020 年`；百分号紧贴数字。数字与量词使用不可断开的语义容器。
- 同一概念只强调首次出现，后续保持正文样式。
- 笔记、公众号 SVG、富文本和其它载体共享同一事实与语言底线，但不共用整段成品文案。宣传材料面向普通读者，根据正式定义事实重新组织内容，不能直接搬运笔记段落，也不能为了版式改写变量含义、数字、公式或边界。颜色、圆角、间距和卡片布局由各载体公共模板维护，不反向写成第二套定义规则。
