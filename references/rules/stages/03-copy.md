# 3. 纯文案

## 1. 这一步做什么

根据主线程合并并经实际数据核实的定义方案、官方证据和当前 raw/codebook，在现有 `文案.md` 中写完标题、摘要、原始问卷、Criteria、小book提示和参考资料说明。内容在本步写清，不交给后置审核补定义。

使用[文案模板](../../../templates/reader-copy.md)；有问卷时使用[问卷模板](../../../templates/questionnaire-copy.md)。本页规定每栏写什么，模板规定怎样填写。需要看完整短例时，读[判断示例](../copy-examples.md)的对应部分；示例中的主题事实不能套用到本次定义。

新主题或定义事实变化时，在正式 R 前完成[变更影响](../validation.md#定义变更影响)；未决事实返回方案环节。只修表达时，读取当前完整文案和必要的已验收方案/代码片段，沿用未改变的证据与复核，按[修正范围](../validation.md#修正后的复核范围)交接，不重开探索。只改某一栏目时，记录实际范围，不顺手修改其它内容。

## 2. 共同写法

- 初稿依据已确认事实写；旧笔记、Criteria、HTML和历史脚本在初稿完成后用于查漏，不作为事实权威或措辞底稿。事实相同不必刻意换词。
- 写清具体对象、条件和结果，不照译程序或用内部术语代替解释。普通读者不能理解的词才补充释义；名称已清楚时不重复解释。只保留影响理解、判定、比较或使用的信息，不以短句数量、禁词或改写率判断质量。
- 不把同一段说明在不同栏目重复粘贴。同一事实确实需要再提时，要说明本处不同的用途，例如摘要说明总分怎样组成，定义逻辑写完整计算条件。同一栏目不换句话重复，也不为缩短文字删掉必要条件。
- 标题准确覆盖实际定义，不扩大对象或概念范围，也不堆全部变量。中英文标题使用含义一致的常见表达。所有读者可见名称须保持对象、方向、时间、单位和分类一致；原始变量标签说明原题，定义结果标签说明最终变量。
- 使用“原始变量”称呼数据来源；原始变量名只在追溯或区分来源需要时出现。代码身份不改名，解释文字写成读者能理解的内容。
- 写作和公开 R 不共用整段文字；公开 R 按[第4步](04-public-r.md)随代码解释。其它载体也只能重新组织已确认事实，不能产生新口径。

## 3. 摘要：最终得到什么

摘要回答两件事：**最后得到什么；这些结果之间是什么关系。** 按下面的顺序写：

1. **先介绍结果。** 有总分、总量等综合结果时，先介绍它；有按它划分的类别，也一起介绍，再写分项及有效回答数等辅助结果。没有综合结果时，按结果实际描述的对象介绍，不凑一个总结果。多个结果要写最终变量总数，单个结果直接点名，不写“等”。
2. **再说明关系。** 哪些分项相加、取平均或加权得到总结果，分数高低表示什么，都要写清。分段分类要说明哪些分数或条件对应哪一类，不能只说“越高越好”。两个结果相互独立或可能重叠、不能直接相加时，也要说明。只写已确认的关系。

名称用中文双引号，强调格式见模板。可以逐项列名，也可以按实际测量内容成组介绍，但不能只写“若干分项”或代码范围。名称已经说清含义，就不用再解释一遍；只有名称不清楚时才补对象、时间、单位或含义。不漏结果，不要求把每组题目再概括一遍。

**“结果怎样组成”和“原题怎样计分”分开放：**

| 要说明的内容 | 放在哪里 |
| --- | --- |
| 分项得分相加得到总分；总分达到已确定的阈值对应哪一类 | 摘要；Criteria仍须写完整计算和分类规则 |
| 原题回答“是/否”各记几分；哪些原题反向计分；每项具体权重；缺几题还计算、有缺题怎样处理 | 对应变量的Criteria，不放摘要，也不放摘要关系树 |

这一区别不以句子长短判断。例如，“四个维度得分相加得到总分”说明结果之间的关系；“正向原题反向计分后求和”已经在说明原题怎样计分。

开场展示顺序为：**定义结果 → 必要的关系树 → 原始问卷与时期说明 → 必要的小book提示 → dbCodeBook目录入口**。多层组成关系可用已确认的结果名称、范围和公式画树，单层结果不画。不在摘要写检索过程、逐年来源代码或另加变量表；使用限制按第6节安排。

目录入口由第5步的summary_source单独生成，文案摘要不重复写目录句。入口使用已核实完整目录，共享父目录只写一次；来源分散时，主要目录与其它来源说明分开传入（格式见第5步）。探索过程留在过程记录。

## 4. 原始问卷：调查实际问了什么

按真实时期组织，每期先写一个“问卷设计”说明，再展示参与定义的原题。说明询问对象、核心问题、提问程序及这些信息用于哪些结果；以自然段或实际对象/问题组组织，不机械编号。问题概括使用中文双引号，不冒充逐字原题，也不逐题复述下面的题块。某期缺少或改变的问题直接说明，不藏在“除……外”的从句里。

首期说明本期情况；后续先说明本期问了什么，有已核实变化才另段说明变化。某期问法不能写成所有时期共有；各期题块不能用“同上一期”代替。

原题保留题号、完整中文题干、选项、单位及影响定义的进入条件和跳转；结构化题干不加引号。访员提示、卡片及无关支路只保留影响题义或取值的部分。相同选项可集中说明共同适用题目，但题干和实际差异不能省略。录入与出口写法见问卷模板。

调查事实依据该期问卷或调查说明，发布数据的记录方式依据对应数据材料或实际记录，本定义的赋值写入 Criteria。发布记录方式只有影响原题与原始变量的对应关系时才补充，并明确其主语；不能从文件缺少变量推出调查未问。

按人物、机构或项目反复提问时，说明实际对象和每次记录的信息，不从变量后缀或列数推断人数上限及顺序。数量只在核准且帮助理解时写一次；跨期总数按完整来源身份去重，未确认互不重叠时不把各版本数量相加。

没有原题的来源不凑问卷栏目；混合来源只展示实际核实的题目。只能确认题意时写概括及无法逐字引用的原因，不伪造原题题块。主题过大时返回方案按独立研究问题拆分，不拆散同一变量或定义链，也不靠删题缩短；必要的共同筛选题仍保留在各相关主题。

## 5. Criteria：每个变量怎样得到

按最终变量逐项填写，名称与顺序和定义方案一致。有组成项和总结果时，本栏先写组成项、后写总结果；摘要仍按第3节先介绍总结果。

| 栏目 | 写什么 |
| --- | --- |
| 定义 | 一句话说明变量表示什么，包括必要的对象、回顾期或单位；不写调查年份、来源代码和处理过程 |
| 定义逻辑 | 写清用谁的哪些回答、满足什么条件时记什么值。涉及多个来源时写先用哪个；涉及公式时写输入、计算方法、缺项怎样处理。确实有补零或特殊缺失时写明条件 |
| 分类 | 逐项写方案确定的最终取值和含义，与定义逻辑一致；不能用原问卷编号替换结果编码，方案保留英文类别时就保留该类别。连续变量写类型和单位。观察范围、极端值和非定义性的理论最大值留在 QA |
| 注意点 | 使用这个变量还需知道的来源说明或限制，例如不同年份口径不同、与另一种总分或阈值不可直接比较。不重复赋值步骤；没有就省略 |

- 单题写题义、真实回答选项和赋值。相同判定合并写，只有来源名称变化时不按年份重复规则；直接回答与推导混用、来源优先或回填时，说明适用时期、条件和顺序。
- 按实际计算顺序写，不凑步骤。公式写清输入、单位/时间换算、权重，以及缺少输入时结果怎样处理。只按已有总分分类时，不重复总分之前的清洗。多个变量共有的对象或时期条件可以先说明，简单赋值不加背景段。
- “确认没有发生”与“缺少回答”分开处理；不知道是跳题还是漏答时不能补零。真实特殊编码、影响结果的缺失条件要写清；程序为防运行出错而写的兜底不搬进文案。原值按单位保留时，不补方案未要求的筛选条件。
- 原始选项不改写成推算值。依据题目前提或裁决作出的换算，在注意点说明依据与限制；某期缺来源时交代缺什么、怎样赋值、能解释什么。
- 正常执行发现原始回答矛盾时，按已确定直接来源分别保留，不擅自补零、改缺失或协调结果。生成规则写定义逻辑，影响按范围放注意点或小book；能忠实生成则继续，单个结果无法确定则返回方案。专项扫描和冲突记录按[验收流程](../validation.md#原始回答冲突)，不为每个主题新增扫描。

## 6. 小book：跨变量或整个主题的使用限制

先判断这条提醒放在哪里：

- 只影响某个变量怎么使用，放这个变量的Criteria注意点。例如某个总分与另一种缺失处理口径不可直接比较，或同一量表的历史阈值不同。
- 一组变量共用一个计算或缺失条件，在这组Criteria讲清。不因涉及多个变量就生成小book。
- 只解释问卷为什么有这些题或原始变量，放问卷说明；解释最终结果怎样组成，放摘要。
- 来源、年份或记录方式的差异，影响了不同组结果的共同使用或整个主题，且放在上述位置不能讲清，才写小book。例如家庭支出和债务被重复连接到每个家庭成员，直接按个人行汇总两项金额都会重复计算。具体归属也可对照[短例](../copy-examples.md#小book是否成立看新增的使用含义)。

每点写清：**实际有什么情况，会影响读者怎样比较、汇总或解释结果。** 本次确实作了处理才补处理结果。提到其它变量时，说明它在本主题中起什么作用；不搬入无关主题编号、QA计数、制作过程或完整赋值步骤。

同一限制保留一个主要说明位置，不把其它栏目重复汇总成卡片。通常2至4个短段，只有一点就写一点，超过时先去掉重复内容。没有符合条件的提示，文案写“本主题没有需要单独提示的主题级边界”，成品省略卡片。

## 7. 参考资料与交接

参考资料只收录直接支持方法、公式、计分、阈值或解释限制的已核实材料；普通应用文章留在过程证据。每条说明材料讲什么、支持本主题哪部分、哪些相关处理仍由本项目决定；未说明的内容不能写成文献结论。

问卷事实已在时期说明和原题展示时不重复列作方法文献；官方材料额外规定派生方法时，只引用它支持的部分。实际使用的证据未登记时，先回到探索记录完成真实核对，不事后编造调研。材料选择依据见[证据与文献](../evidence-and-literature.md)，格式使用文案模板。

交接前集中完成：

1. 对照方案检查结果、含义与关系没有遗漏；对照官方原文及每个选项检查题文和路径，不能只检查记录中已有条目。原文与记录不一致时回到证据裁决，不为通过检查机械改成相同；记录只读时报告差异。
2. 按读者顺序通读：摘要是否先介绍主要结果，有没有混入原题计分或缺项处理；每个变量能否按Criteria得到确定的值；小book提醒了什么使用问题，为什么不能放在某个变量的注意点。发现放错位置就在本步改。结论说明实际判断及修改，不把“这些内容都写了”当成“写对了”；不另建审核表或审核角色。
3. 运行 `check_reader_copy.py --copy <文案> --record <来源记录>`，集中处理差异。它检查结构、Criteria顺序、摘要格式标记及已登记题文，不判断摘要内容该不该写、小book该不该有或文字是否好懂，也不证明官方记录完整。
4. 在现有执行结论保存发现及修改结果；使用 `stage-finish --stage-id copy --copy <文案.md> --summary <实际结论>` 保存首稿并交接。事实缺口返回方案，表达问题在本步修正。保存版本不表示内容通过。

正式生成从定稿文案读取，不在 R 中再写一份。文字需改时先改文案；[生成环节](05-generate.md#文案读取与展示)负责接口、样式和生成前后的一致性，[成品交接](07-review.md)沿用本步结论，不重新发明写作标准。
