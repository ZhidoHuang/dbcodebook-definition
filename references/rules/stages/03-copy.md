# 3. 文案写作

## 执行与读取

先完成下面的输入判断，再读取所选任务。写作顺序按依赖安排，成稿按展示顺序组装。

### 先确认输入与范围

1. 从用户请求确定本次范围：完整新稿、整篇更新、指定栏目修改、只读审核或正确文稿的显示问题。沿用已有明确范围，不要求用户重新填表。
2. 读取已定方案、来源证据和下载后必要的实际数据结论，定位最终变量、时期、结果关系，以及已有的展示决定和省略理由。按下方[模块展示例外](#模块展示例外)确认展示模式。使用现有 `definition_plan`、`approved_analysis_vars` 和相关题目的展示字段；记录结构不同时按实际字段定位。探索记录中有适用的明确用户裁决时一并沿用。
3. 核对这些结论是否对应当前输入和本次修改。文件存在或历史检查通过不证明当前证据齐全。事实缺口返回来源阶段核实受影响部分；已有且未变的有效内容不重新研究或重写。
4. 已有展示决定且未受修改影响时，直接采用。尚未决定的依据、问卷和树，先读本页下方对应的展示判断，再选择任务；不要先加载完整专项规则来替代这一步。

大记录先定位上述字段，再读取所选任务需要的完整事实。输出被截断时补读遗漏范围，不以截断结果作已读完的证据；不按变量重复读取未变规则。不要求为这个判断新增记录文件。

结果关系在[来源方案](01-source-plan.md#结果关系确认)中确认。本阶段复核并表达，不重新选择业务方案。模板不能覆盖正式规则或已确认方案。

### 按确定的范围读取

下表中的“任务及写法”是同一步的读取内容。已读且未变时沿用；仅定位链接或看过任务标题不等于读过对应写法。

| 已确定的操作或条件 | 任务及写法 | 后续或省略边界 |
| --- | --- | --- |
| 写完整新稿或更新整篇 | 先读本页共用要求，再按下方执行顺序读取普通写作任务的对应章节 | 专项任务由实际展示决定触发，不通读整个实例集 |
| 只改标题或摘要 | 本页共用要求；[标题与摘要任务及相邻模板](../copy/core.md#标题与摘要任务) | 只有关系树实际受影响时再读树任务 |
| 只改 Criteria | 本页共用要求；[Criteria任务及相邻模板](../copy/core.md#criteria任务) | 不改变已有定义；涉及的表达仍不清楚时定位相关实例 |
| 只改小book | 本页共用要求；[小book任务及相邻模板](../copy/core.md#小book任务) | 仅有具体表达困难时读相应数据结构或差异实例 |
| 只改参考资料 | 本页共用要求；[参考资料任务及相邻模板](../copy/core.md#参考资料任务) | 沿用实际采用材料，不重新扩展检索 |
| 决定展示或修改问卷 | [问卷任务及基础题块](../copy/questionnaire.md) | 跨期变化、内部小标题或题意概括成立时，分别读取该任务链接的对应实例 |
| 决定展示或修改定义依据 | [依据任务](../copy/basis.md)及其[对应写法](../../../templates/reader-copy.md#定义依据) | 一套依据读一套依据写法；存在实际多方案比较才读比较实例。省略本节则不加载本任务 |
| 决定展示或修改关系树 | [树任务](../copy/tree.md)及选定结构的[骨架或实例](../../../templates/reader-copy.md#关系树模板) | 选定结构后取对应一种；没有右侧汇合时不读汇合例 |
| 完整文案，或修改涉及本库来源、身份、时期、编码或接口 | 从[数据库路由](../../database-routing.json)读取所选库对应差异 | 只读与当前文案有关的段落；其他库和未触发的运行差异不加载 |
| 只读审核 | 受审操作的任务、写法及其验收依据 | 不保存生产快照、不生成或同步 |
| 正确文稿的显示问题 | [第5步对应显示要求](05-generate.md#展示标准) | 区分文稿、解析、生成和网站责任，不先改业务含义 |

既有成果按[变更影响](../validation.md#定义变更影响)确定范围；材料保留按[执行材料](../write-boundaries.md#执行材料)，生成按[已有成果接口](05-generate.md#已有成果的生成接口)。用户明确只修本地问卷时，进入[Questionnaire-only](../scoped-tasks.md#questionnaire-only)。只读取选中入口，不因此读取整个局部任务集合；读取完整原稿也不等于读取全部规则。

### 按依赖执行写作

完整新稿按以下顺序执行；局部修改只进入受影响步骤。

1. 从[最终变量清单](01-source-plan.md#最终变量名称与展示顺序)取得每项的代码名、中文显示名、最终取值或单位、时期及必要条件。按变量代码定位对应方案项，名称、分组和顺序直接沿用；这些输入共同用于 Criteria、树及后续 R 和字典。缺少事实或关系未定时，返回来源方案处理该项，不在各栏目分别补定。
2. 按已确定的展示范围准备依据和问卷；两者没有固定先后关系。使用上表对应的任务和写法。
3. 完整模式读[Criteria任务](../copy/core.md#criteria任务)，按本变量实际采用的方法编写定义逻辑；符合[模块展示例外](#模块展示例外)时省略该任务。
4. 读[标题与摘要任务](../copy/core.md#标题与摘要任务)，根据已明确的定义编写摘要。需要树时，按[树的编写顺序](../copy/tree.md#编写顺序)将同一份方案填入选定模板；完整模式使用已确认的分类和单位，简化模式直接取方案中的对应内容。
5. 读[小book任务](../copy/core.md#小book任务)和[参考资料任务](../copy/core.md#参考资料任务)，编写实际需要的内容，再按[组装任务](../copy/core.md#组装任务)完成文案。
6. 按末尾“检查与交接”保存和检查。结构或表达问题在本阶段修；事实问题返回来源；检查通过只证明实际核对的内容。

### 通用表达

规则与生成文案均借鉴 ASD-STE100 的受控写作原则。以下为中文表达要求，不宣称符合该英文标准。文案范围包括摘要、关系树、定义依据、问卷说明、Criteria、小book和参考资料说明。

- 用具体对象和动作说明事实，像正常向读者解释问题一样写。可以使用必要的专业词汇；含义不明显时就近解释，不自创简称。
- 一句话表达一个意思。先写条件，再写对应处理；例外紧跟对应处理。不用长串分号压缩。定义逻辑的分项按 [Criteria 格式要求](../copy/core.md#5-criteria每个变量怎样得到)执行。
- 同一概念使用同一名称。名称已经清楚时，不再重复释义。
- 完整保留必要的时期、对象、条件和例外，不为短句删掉限定，也不机械限制句长。
- 同一信息放在最合适的位置；再次提及时应有不同用途。
- 全篇名称的对象、方向、时间和单位保持一致。
- 初稿依据本次已确认事实，不照抄旧稿；来源不明、方案未定时先解决事实问题，不在写作时自行增加口径。

### 通用格式

使用 Markdown，不手写 HTML 或 CSS。数字与量词间留一个半角空格，百分号紧贴数字。

正文需要写出原始变量名、下载别名、最终变量名或程序代码时，使用成对反引号，包括表格说明、小book和问卷备注。本条只规定出现后的格式，不要求额外列出这些名称。单个变量写成 `db010`；多个变量分别标记，如 `db010`、`db011`。完整代码表达式或公式放在同一对反引号内，如 `ADL_count = ADL_dressing + ADL_bathing`。

编码值、解码标签、回答选项、类别名称和中文结果名称使用普通文字，不用 inline code。按栏目要求加方括号时，写成 [0]、[Female]、[Less than 1]，不再套反引号。最终分类标签按[最终变量取值](01-source-plan.md#最终变量取值)确定；来源原文中的下划线不改变上述排版要求。代码块内已是代码格式，不再套反引号。

以下位置不另加 inline code：

| 位置 | 写法与显示 |
| --- | --- |
| 问卷题目标题 | 写原问卷变量名题号，由生成器加粗 |
| 问卷跳题说明 | 条件和去向中的变量名题号用普通文字，如 → 跳至 C109 |
| 定义表、结果卡片中的变量标题 | 文案用纯变量名作三级标题，如 `### ADL_count`；生成器处理显示 |
| 可点击的来源映射区域 | 由生成器和网站处理，不在文案中手写 |
| 关系树 | 使用[树任务](../copy/tree.md)规定的语义标记 |

### 写作前先复核两件事

1. **复核已确认的结果关系。** 对照[来源方案中的结果关系](01-source-plan.md#结果关系确认)，确认文案未把并列、组成和计算关系混用。关系未定时回来源方案，不通过树的布局代替决定。
   关系树的使用条件见[摘要](../copy/core.md#3-摘要最终得到什么)，问卷展示和分组见[问卷](#4-问卷调查实际问了什么)。
2. **判断是否有公认且适用的统一标准。** 核对已核实指南、原始方法或技术资料的人群、版本及数据适用性。
   只有一篇论文，或多篇论文引用同一框架，都不足以证明具体计分统一。
   展示一套标准还是比较多套方案，按[定义依据](#定义依据先说明标准再说明本次采用什么)处理。

使用文献和问卷已有的概念名称，不为上述判断增加新的主题分类名称。
不得自行发明概念、量表名称或标准，也不将本次内在能力的成分与算法套到其他主题。


## 模块展示例外

来源方案中的 `topic_kind` 记录 `module`（模块）或 `standard`（普通定义）。文案顶部YAML进一步区分模块的展示类型：

| 定义内容 | 文案 `topic_kind` | 来源方案 `topic_kind` |
| --- | --- | --- |
| 含问卷定义的模块，包括问卷与检测指标混合的模块 | `questionnaire_module` | `module` |
| 不含问卷定义的模块，如实验室检测、身体测量、DXA | `module` | `module` |
| 普通定义 | `standard` | `standard` |

只有文案类型为 `module` 且最终定义变量数 **大于10** 时，采用下方简化展示。其余情况保留完整Criteria。组分概览、详情的展示对象统一按[生成规则](05-generate.md#正式输出与图表)执行。程序按实际 `analysis_vars` / `approved_analysis_vars` 计数，不按来源列数或文案标题数计数。

按已确认的定义内容判断是否包含问卷定义，不按笔记是否展示“问卷”栏目判断。更新旧模块时先核实内容；含问卷定义的旧 `module` 改为 `questionnaire_module`。缺少类型声明的旧文件按 `standard` 处理。展示子类型不改变来源方案中的模块身份或计算。

- 不编写逐变量Criteria，也不把这些内容移到摘要、依据、树或小book重复编写。
- 不生成整个 Definition / Criteria / detail 表格及对应的 `_definition.html`。
- 组分概览和组分详情沿用统一的组分、定义展示接口，不生成原始变量。
- 计算、来源、公开R的业务说明及所有数据/字典附件保留；其它文案栏目和图表按原规则。

后台用 `copy <- read_definition_copy(analysis_vars)` 取得程序判定的 `copy$display_policy`，传入 `render_definition_bundle(..., display_policy = copy$display_policy)`；该元数据使读者独立运行R时使用相同展示模式。

## 定义依据：先说明标准，再说明本次采用什么

### 依据展示判断

| 情况 | 写什么 |
| --- | --- |
| 有公认且适用的统一标准 | 写标准名称、来源、版本、适用人群、组成及计分或判定方法，再说明本次时期和数据如何对应；不为凑比较罗列其他方案 |
| 只有一套可用依据，但不足以称为统一标准 | 直接说明内容、适用性和采用理由；不凑比较，也不称其为公认统一标准 |
| 多套实际可比方案在成分、计分或阈值等方面存在实质差异 | 先用一小段交代必要概念来源，再用简短对比表说明主要做法和关键差异 |
| 直接保留原始事实或简单计算，没有标准选择问题 | 可省略本节 |


## 4. 问卷：调查实际问了什么

### 问卷展示判断

**目的**：让读者看到定义所依据的实际问题和提问程序。

**何时展示**：先看本次定义怎样得到。

| 情况 | 处理 |
| --- | --- |
| 需结合前置回答、跳题或多题关系判定结果 | 展示相关题目及理解它必需的条件 |
| 原题含义会影响结果解释 | 展示消除关键歧义所需的题目及条件 |
| 直接采用已发布性别、年龄、官方分类，或按家庭人数等于 1 判断独居 | 通常在定义逻辑说明来源和取值即可，不展示问卷 |
| 混合主题 | 按题组分别决定 |
| 全部题组都不需要展示 | 省略整个问卷部分，不写省略说明占位 |

按题组决定是否展示。展示题组时，保留本主题定义所用的相关原题，以及理解提问过程所需的条件和跳转。不能仅因结果直接取值或 Criteria 已有说明，就省略原题。
问卷只展示题干、选项及理解作答过程所需的说明。代码本中的空白条件、记录状态和内部判断细节留在证据记录与程序中，不搬入正文。其中涉及的必要跳题，整理为简明的触发条件和去向。
同一原题对应多个数据字段时，合并展示原题并列明字段，不重复列题。跳转到本主题内的相关题目时，应能在本期题组中找到该题；跳出本主题时说明去向，不为此抄入无关模块。

研究时仍须核实必要问卷和官方材料，并在探索记录保留证据；不能因正文省略而删除研究证据。


### 关系树

**目的与使用条件**

优先用关系树展示定义内容及其关系，包括组成、计算、分类和内容分组。人口学等并列结果也可按内容分组，但不能把分组画成计算关系。关系树不能帮助读者理解时，才省略。

关系树不代替定义方案或 Criteria。

决定省略时，在现有来源记录的 `tree_omission_reason` 中填写具体理由；展示树时不需要此字段。执行者核对理由是否符合上述使用条件。程序只检查省略理由是否已记录，不替代这个判断。

## 检查与交接

完整新建或重做任务的文案检查从现有执行报告识别 `full_definition`，要求方案的每个最终变量都有 `display_name`。有树时，核对结果绑定、顺序、已确认显示名和取值或单位 meta；无树时，核对上述省略理由。正式 R 预检使用同一检查。缺少输入时回到方案或树文案补齐，不以旧格式兼容代替首次生成要求。名称是否准确、meta 内容是否正确、树是否有助理解，仍由执行者核实。

1. 新主题或定义事实变化时，在正式 R 前按[变更影响](../validation.md#定义变更影响)填写现有记录。仅改表达则沿用未变方案和 R 结论；不能扩展到未指定栏目。
2. 有问卷时完成[问卷证据登记](../copy/questionnaire.md#问卷证据登记)。不展示时也保留原题证据并登记理由；涉及兼容字段或结束主题时，只读取对应条件。
3. 当前 copy 环节运行中，执行下面的命令。程序登记当前文案绑定后检查，不保存逐版副本。只读检查不传 `--process-dir`。

```powershell
& $Python -X utf8 scripts/check_reader_copy.py --copy $Copy --record $SourceRecord --process-dir $Process
```

4. 修正结构、顺序、题文和格式差异。程序不裁决表达质量、翻译准确或官方证据是否完整。未决事实回来源方案；正确输入的显示错误回生成；规则冲突按入口的覆盖边界处理。主题范围过大时按独立研究问题拆分，不拆散变量链或删必要原题。
5. 用 `stage-finish --stage-id copy --copy <文案.md> --summary <实际完成内容>` 更新当前文案绑定和实际结果。不填写逐栏目 PASS 或通读声明，文件绑定不代表质量通过。
6. 完整新稿交[公开 R](04-public-r.md)；已有成果按[生成环节](05-generate.md#已有成果的生成接口)更新受影响内容。生成器读取这份文案，R 不另写正文。结果验证后接成品交接及已授权同步；明确只读或本地任务按其范围结束。
