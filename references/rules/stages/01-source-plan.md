# 1. 选题与来源方案

## 新设备准备

先按本机配置运行一次环境预检，汇总缺项后一次处理；不要边做主题边发现依赖。已有稳定环境不每步重复运行。

```powershell
& $Python -X utf8 scripts/check_definition_environment.py --config $Config --mode full --browser msedge
```

`$Python` 和 `$Config` 指向本机实际 Python 和配置文件；浏览器参数按本任务选择使用 chrome 或 msedge，不借此切换已有会话。仅本地生成用 --mode local；仅网站同步用 --mode browser，不检查无关 R 环境。检查不会安装软件、联网拉包、打开浏览器或操作网站；临时读写仅用于验证目录与 R 能否工作。

通过后仍按 [浏览器会话](../write-boundaries.md#浏览器会话) 读取已有会话并确认登录，不能把“发现浏览器程序”当作已经可以控制。R 临时目录或包库失败时保留实际错误与路径，不笼统认定中文用户名不支持，不改全局 HOME 或复制整个用户环境。

## 本步执行与验收

- 输入：用户范围、当前任务配置和已有主题索引
- 另读：[证据与文献](../evidence-and-literature.md)、所选数据库 profile 和 workflow 的来源探索/研究口径部分；需要命名时读 [来源命名](02-download.md#来源命名)
- 执行：核对网站真实目录与问卷整体，列出候选取舍、时期、对象、分析单位、路径和所需来源；执行时完成来源和口径核对，形成稳定方案
- 交付：探索记录、definition_search_record.json 和 download_selection.txt
- 程序检查：下载准备入口调用 check_definition_source_record.py --selection-file，检查候选、身份、用途、计划路径及逻辑问题是否解决
- 模型判断：每个概念是否有意义，范围是否充分，官方材料能否支持每条判定，结构性缺失是否解释得通
- 未通过：补齐缺失证据或修订方案，不启动下载；必要研究裁决向用户反馈

来源检查在本步完成，结论写入现有 logic_review 和 logic_issues；字段名称不表示已经独立复核。下载前仍须解决来源缺口和研究歧义，不预填通过。

通过本步才交接给下一步；一次命令或点击不是一个独立验收环节。只读复核者接收本步稳定输入、对应标准及具体问题，不接收整个历史对话。

主执行者逐项确定来源是否完整、范围是否片面、问卷路径是否闭合、时期与对象是否准确、分析单位和身份键是否合适，以及每个来源变量的实际用途。存在未解决问题时不得下载。独立复核与第4步 R 实现复核合并，使用同一份来源方案，不另外创建固定的下载前审核。

确有本步无法解决的研究问题，按 [异常独立验收](../validation.md#2-独立验收仅有四个入口) 定向核证或请用户裁决；不因为要减少审核而猜测口径。

下载前核对计划中的进入条件、题目路径、所需来源和定义结果，不要求尚未下载的数据已有实际统计。路径的 `observed_count`、`unexplained_count` 及实际闭合标记在未核对时保留 `null`，不能预填0或通过。下载后用本次实际数据补齐人数并核对每条路径；正式运行与最终来源验收仍要求人数有效、未解释人数为0及实际路径闭合。下载前通过只允许提取，不表示结果已验收。

“定义是否片面”分两层：先依据用户主题和已定位的问卷/官方材料判断应覆盖哪些研究概念，说明主要候选为何纳入、另属哪个主题或暂不纳入；再检查每个已选变量的构造是否完整。取舍写入现有 `candidate_decisions` 和探索记录，不新增记录体系。围绕既定结果筛选原始字段，只证明这些结果的来源用途，不证明主题范围充分；重做也不能把旧变量集合默认为已批准的完整范围。
