# 1. 选题与来源方案

执行记录：定位任务用 `locate`，实际来源探索用 `sources`。

## 新设备准备

迁移配置、中文临时目录、离线 CLI 和首次索引见 [新设备配置](../../new-device.md)。先按本机配置运行一次环境预检，汇总缺项后一次处理；不要边做主题边发现依赖。已有稳定环境不每步重复运行。

```powershell
& $Python -X utf8 scripts/check_definition_environment.py --config $Config --mode full --browser msedge
```

`$Python` 和 `$Config` 指向本机实际 Python 和配置文件；浏览器参数按本任务选择使用 chrome 或 msedge，不借此切换已有会话。仅本地生成用 --mode local；仅网站同步用 --mode browser，不检查无关 R 环境。检查不会安装软件、联网拉包、打开浏览器或操作网站；临时读写仅用于验证目录与 R 能否工作。

通过后仍按 [浏览器会话](../write-boundaries.md#浏览器会话) 读取已有会话并确认登录，不能把“发现浏览器程序”当作已经可以控制。R 临时目录或包库失败时保留实际错误与路径，不笼统认定中文用户名不支持，不改全局 HOME 或复制整个用户环境。

## 本步执行与验收

- 输入：用户范围、当前任务配置和已有主题索引
- 另读：[证据与文献](../evidence-and-literature.md)、所选数据库 profile 和 workflow 的来源探索/研究口径部分；需要命名时读 [来源命名](02-download.md#来源命名)
- 执行：核对网站真实目录与问卷整体，列出候选取舍、时期、对象、分析单位、路径和所需来源；执行时完成来源和口径核对，形成稳定方案
- 交付：探索记录和 definition_search_record.json，包含已确定的完整来源身份与最终别名；download_selection.txt 由[第2步固定入口](02-download.md#固定选择与别名输入)生成，本步不另写一份
- 程序检查：第2步下载准备入口调用 check_definition_source_record.py --selection-file，检查候选、身份、用途、计划路径及逻辑问题是否解决
- 模型判断：每个概念是否有意义，范围是否充分；题义、访谈对象、原始选项和问卷跳题规则是否与官方材料一致；分类、阈值和构造方法是否有相应依据，属于本次选择的是否说明理由；结构性缺失是否解释得通
- 未通过：补齐缺失证据或修订方案，不启动下载；必要研究裁决向用户反馈

先区分用户要“新主题”还是“修改既有主题”，将该范围写在探索记录开头。既有主题可以提供口径参照，但内容重叠不代表获准扩充旧主题；用户已说明独立新建时，沿用该决定，不再向旧主题目录写过程文件或请求重复确认。

本步由主线程确认来源与口径问题已解决、方案及记录已完成后，交接第2步下载准备。第2步固定入口生成 download_selection.txt 并执行程序检查，检查通过后才允许实际下载；检查失败则返回修订对应问题。一次命令或点击不是一个独立验收环节。只读复核者接收本步稳定输入、对应标准及具体问题，不接收整个历史对话。

## 双路探索与主线程合并

### 准备相同的探索任务

先从本次要求和已确认上下文整理三项：已确定的要求、待探索的问题、材料与线索。没有研究问题的局部写作、生成或同步直接进入对应环节，不重新探索。主题方向是输入，最终主题范围是结合数据信息形成的产出；用户已限定的范围不能擅自扩展。

两个内部 subagent 接收相同任务说明和材料入口，不看对方过程或结论，不接收主线程预选答案。每路连续完成下面的范围、来源和方法探索，不按每个小问题重新派一对代理。浏览器各用已绑定的独立标签，不能共享当前页，也不各自付费下载或发布。

### 两个代理各自查什么、怎样判断

1. **确定主题范围。** 探索相关目录、变量和官方问卷。具体主题定义还要检索相关研究，了解已有研究通常纳入哪些概念、怎样界定主题范围、使用哪些常见指标；只查看数据模块提供什么时，不强制检索文献。文献作为发现候选的线索，结合各期官方问卷、实际变量和用户已限定的范围判断是否纳入，说明主要候选为什么纳入、另属哪个主题或暂不纳入；将影响范围判断的文献及取舍理由写入探索记录。已有材料是线索，候选不限于旧主题变量集合；只找到预选变量的来源，不代表主题范围已经充分。
2. **查清具体来源。** 逐期核对题义、选项、访谈对象和分析单位，确定具体来源身份及用途，辨认跨期变化。
3. **结合问卷和网站分布判断跳题。** 从目标题向前查，弄清楚什么回答会跳过哪些题。到网站查看对应年份的记录数和选项人数，比较前置题和后续题的回答人数、分布，辅助判断跳题后的结果应该怎样处理。区分前置回答已足以确定结果、因年龄或访谈对象等原因未问、普通未回答；不能只因为某题没有回答或被跳过，就补成0。按下表确定哪些前置变量必须查清并纳入来源，即使它们不作为最终输出变量。

   | 本次需要做什么 | 来源如何选择 |
   | --- | --- |
   | 根据前置回答补值、筛选对象、改变分类或计算结果 | 纳入判断这些条件所需的全部变量 |
   | 单独输出缺失原因，或已定方案要求逐人核实某类未问原因 | 纳入识别该原因所需的变量 |
   | 几种已知原因都保留NA，不分别输出或统计原因，且区分原因不改变赋值、样本或必要验证 | 在探索记录说明这些问卷设计及处理理由，不为区分原因额外下载变量；只统计这一合并缺失分支，不声称已识别各原因人数 |

   例如，同样没有回答，若前置回答决定补0，就必须取得该前置变量；若两种原因均保留NA且本次无需区分，可合并记录。未知编码、相互矛盾的回答或与已知设计不符的缺失，仍须调查，不能并入NA掩盖问题。需要哪些验证在本步说明理由，第6步按此核实。

4. **形成定义方案。** 根据题义、完整跳题条件和网站分布，说明各结果怎样赋值、分类、计算和处理缺失。先写问卷明确给出的事实，再写这些事实怎样支持本次推导：哪些前置回答足以确定结果、哪些情形不能判定。目标题已有直接回答时，说明是否还适用补值；前置回答之间出现矛盾时，说明是否仍满足补值条件、结果怎样赋值及理由，不能只写“保留原答并记录异常”。问卷未规定的冲突处理属于本次定义选择，不冒称官方规则。将推导标明为本次定义选择；网站单题人数用于核对合理性，联合条件及实际实施情况留待下载后检验。若原文存在简写或矛盾，连同上下游完整路径核对，说明采用哪种解释及理由；只有仍无法确定必要来源或结果构造时才阻断，并具体说明缺少什么证据。尚未完成的查询继续完成，不把“未查完”交给用户裁决。涉及分类标准、阈值或构造方法时，按[证据规则](../evidence-and-literature.md#按问题决定是否探索文献)查方法文献。

每路保留自己的输出，交付建议范围与候选取舍、具体来源及时期/对象/用途、结果含义与构造方法及依据、未决问题及影响。代理完成探索不等于其建议已获采纳。

### CHARLS网页取证固定入口

浏览器及标签先按[会话规则](../write-boundaries.md#浏览器会话)绑定。CHARLS目录、普通搜索和单来源逐期详情使用`source-read`，不在主题中另编目录定位、等待刷新或详情解析脚本。研究者决定查什么，固定入口负责读对页面并保存原文。

在本分支保存一个动作JSON，按需要选择一种：

```json
{"kind":"directory","path":[]}
```

空路径列出顶层目录；之后将返回的目录名称按层级填入`path`，例如`["Core data","Health status & functioning"]`。普通搜索用`{"kind":"search","query":"dressing"}`；详情用`{"kind":"detail","variable":"db010","file":"health status and functioning","periods":["2011","2013"]}`，身份和时期取自本次页面结果，不照抄示例。

```powershell
& $Python -X utf8 "$Skill/scripts/playwright_session_action.py" --config $Config --mode source-read --database charls --action $Action --session $Session --session-workdir $SessionWorkdir --tab-id $TabId --out $Receipt
```

每次只读一个来源、最多6个时期，依次执行并分别保存结果。入口只操作本标签：按完整目录层级选可见节点，监听本次搜索响应并核对表格身份和时期人数，按完整变量/文件/时期核对详情；保留题文全文，不按“跳至某题”的字样截断。搜索返回第一页及总页数，多页结果不能声称全部查看，继续缩小检索定位候选。`NO_RECORDS`只说明该期页面无记录，不证明未采集或可以补0。

只有`ok=true`的本次结果可作取证记录。登录失效按会话规则恢复；目录歧义、结果未更新、详情不一致或超时，保留失败结果；先看返回的中文原因、请求与响应记录、变量/年份及耗时，确定卡在哪一步再处理，不把旧结果填成成功、不自动重放。“未观察到请求”不等于已经证明网站没有发出请求。此入口当前仅验证CHARLS；ELSA/HRS仍按各库规则使用绑定标签入口，不声称已经适配。

### 主线程怎样合并

主线程比较两路的证据、范围和遗漏：一致且充分则继续；互补内容核实后取舍，不直接拼接清单；事实分歧只补查相关材料；方法都有依据时按已明确研究目的选择，仍需用户决定的才提出选项及推荐。两边一致但共同缺少关键证据不能放行。不强求两边改写为一致，也不固定增派第三个审核者。未完成的一路不能用自查代替，继续不依赖它的工作并如实报告。

合并结论统一维护在探索记录和 definition_search_record.json，写清范围、全部结果及必要组成/重叠/独立关系、来源身份与别名、适用对象/时期、赋值/分类/公式/缺失处理、依据性质和未决事项，不另建内容重复的摘要结论文件。采用官方/文献结论与本次合理选择分开；下载前未知的实际统计保留未知。独立输出、合并理由和有效方案按[探索交接](../review-roles.md#双路探索交接)登记后交接第2步下载准备。

两路完整过程留在各自原件。主线程记录只写合并决定、分歧取舍和自己新增的核实，引用分支文件及步骤，不把两路日志逐条拼进主记录。JSON的exploration_log与主记录这些步骤对应；证据条目引用采用该证据的合并或核实步骤，不为保留引用重复抄写整路过程。

## 怎样保存方案

### 最终分析变量命名

先查看已有同主题笔记的标题、中文结果名和最终分析变量名。同一概念且对象、时间、单位和分类含义一致时，优先沿用已有名称，包括完整变量名及其前缀、格式，不仅借用词根，也不为缩短名称另起一套。含义不同或旧名不准确时，说明原因，再加必要限定或另起名称。

没有可沿用名称时，新名称尽可能简短且能联想含义；同一系列使用共同前缀，便于在大量分析变量中快速定位，有适用的既有系列则延续其前缀和格式。不把处理步骤写进名称，也不删掉区分即时/延迟、状态/数量、单项/汇总等含义所需的部分，不机械复制其它数据库的前缀。

选定名称写入现有定义方案，文案和 R 直接使用；不借统一命名批量改旧笔记，也不另建命名台账。优先沿用已有名称的要求只针对最终定义结果；来源变量及下载别名按[来源命名](02-download.md#来源命名)处理。

### 保存来源与定义记录

来源检查在本步完成，结论写入现有 logic_review 和 logic_issues；字段名称不表示已经独立复核。下载前仍须解决来源缺口和研究歧义，不预填通过。

探索过程按[探索记录模板](../../../templates/exploration-record.md)同步写实际发现、决定和下一步要查的具体问题，并注明证据文件或材料位置。网页完整返回内容保存在原文件；记录只摘出影响判断的事实和必要人数，不复制整份返回内容，也不用“继续核对”等套话代替决定。JSON中的 exploration_log 简要记录同一步的事实、决定和理由；完整原题、选项及来源身份仍按各自字段要求保存，不因过程文字简短而省略。

使用 templates/definition-search-record.json 的字段结构。各来源组及候选概念可引用同一来源，保留各自用途和时期；第2步程序汇总去重，不为去重删除关联或合并不同口径。`source_identities` 中每项填写网站完整 `Variable (File)`，与同组 `raw_variables` 的最终下载别名按位置一一对应。`periods` 按真实单期逐项填写（例如 `["2011", "2013", "2015"]`），覆盖记录和路径记录的 `period` 每条只对应其中一个时期，不能写成 `2011-2015`。批量更新这些 JSON 关系时使用结构化读写，避免对单行长 JSON 做多次局部字符串替换。

两路独立建议保留 `status=DRAFT`，在交付说明中写明本路是否完成及未决问题；完成探索不等于获准下载。主线程比较后在正式记录中保存采用的方案，问题解决后设为 `READY`，再登记合并并交给第2步。保留两路原件，不用改状态代替实际合并，也不把独立建议直接当正式清单。

来源原文保留在question_text；第3步另外登记中文展示，不用译文覆盖原文。

`questionnaire_evidence.options` 逐期从已定位的原题录入，编码按原文字符串保留（如 `01` 不改成 `1`），不按选项次序重新编号；只有各期原文一致时才共用选项。这里记录问卷原样，发布数据取值与最终结果编码另归来源比较和定义方案。脚本批量编制时从各期证据取值，识别缺项或歧义就报错，不用统一默认选项补齐。

需要用前置回答补值时，把完整触发条件、适用时期、受影响结果及证据写入现有 `questionnaire_path_closure` 和 `definition_plan`；全部判定所需的前置变量纳入来源组和下载范围。某期经证据核实未采集或未发布所需来源时，记录缺项证据、确定的处理及结果解释范围，作为已明确的资料限制。必要来源仍未查清，或缺失后的处理尚未确定时，属于未解决的来源缺口，不得启动下载；仅说明“缺什么”不算解决。候选取舍写入现有 `candidate_decisions` 和探索记录。

## 下载前后怎样交接

下载前核对计划中的进入条件、题目路径、所需来源和定义结果，并使用网站已提供的记录数和回答分布分析。`questionnaire_path_closure`按本次赋值、筛选和验证分支填写；按上表合并的NA分支写清范围和可执行条件，`required_raw_variables`列出识别该分支实际使用的字段。需要联合多题才能确定、网站尚未提供的人数，留待下载后用本次数据核实；不能把单题选项人数直接填成多题共同条件下的路径人数。路径的 `observed_count`、`unexplained_count` 及实际闭合标记在未核对时保留 `null`，不能预填0或通过。下载后用本次实际数据核对这些分支的人数、结果和异常；`unexplained_count=0`表示没有尚未处理的赋值或路径问题，不表示所有NA的调查原因已逐人识别。下载前通过只允许提取，不表示结果已验收。

下载后按计划核实实际编码、覆盖和路径人数。读取或实现错误直接修；已知跳题按方案处理。出现会改变范围、来源或定义且现有证据解释不了的问题时，只针对该问题双路调查；未变方案作为共同约束。方案变更更新合并结论及受影响验证，来源变化按第2步重下，不重做无关探索。统计补记或问卷展示定位不算研究方案改变。
