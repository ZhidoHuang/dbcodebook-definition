# 普通写作任务

先按[模块展示例外](../stages/03-copy.md#模块展示例外)确定适用栏目；本页逐变量Criteria要求用于完整模式。完整写作依次完成适用的Criteria、标题摘要、小book和资料，再组装。已完成且未变的内容沿用；局部任务直接定位本次操作，不顺序重写其他栏目。
共用表达、inline code、依据/问卷/树的触发条件均以 [文案入口](../stages/03-copy.md) 为准。

## Criteria任务

- 入口：相应变量的已定事实足以说明取值。
- 输入：最终变量清单、来源、时期、算法和特殊缺失条件；结果关系已在方案确认。
- 操作：按最终变量清单的顺序，以 `analysis_var` 作三级标题。将该项的含义写入“定义”，构建方法写入“定义逻辑”，最终取值和单位写入“分类”；必要使用限制写入“注意点”。各栏目按下方写法表达，树和字典也取自这份方案。
- 产出：与最终清单一致的 Criteria，不新增输出变量。
- 验收：对照已定方案，核对每个变量的方法、时期、边界和特殊处理；确认变量名符合下方层级要求，没有加入仅适用于其他变量的处理，也没有遗漏影响取值或使用的条件。机械格式检查不能代替这项核对。
- 失败：事实或方法未定回来源；已定事实表达有误留本任务；实现错误归公开 R。

## 5. Criteria：每个变量怎样得到

**目的**：让读者理解每个变量，并能据此判断一条记录该取什么值。

- **内容要求**：每个最终变量填写一组，名称及顺序与方案的最终变量清单一致。
- 当前变量自身的赋值、计算、适用条件及例外，写在其“定义逻辑”中；缺失说明按下方第3项的范围填写。不在 Criteria 开头另放共同处理段落，也不用“符合共同条件”等引用代替实际条件。

| 栏目 | 内容 |
| --- | --- |
| 定义 | 用一句话说明变量表示什么，带上必要的对象、回顾期或单位 |
| 定义逻辑 | 说明使用什么信息，以及如何组成、计算或判定变量，具体写法见下方 |
| 分类 | 按[最终变量取值](../stages/01-source-plan.md#最终变量取值)核对方案，列出有效、非缺失取值及含义。NA 不列为分类。数值变量说明类型和单位。不拿原问卷编号替代结果取值；实际分布留在QA |
| 注意点 | 写影响结果使用的换算依据、时期差异和解释限制。不重复计算步骤，不写执行者的制作要求；没有就省略 |

定义逻辑先讲清变量的取值、计算或判定方法。写明影响结果含义的阈值、截断和替代方法。按实际内容选择文字、公式或表格，展开理解该方法所需的成分和条件，不另拆固定栏目：

1. **每项先讲清题义和处理方法，再标注对应变量名。** 变量名放在对应题义或指标名称旁的括号中，使用 inline code，不能代替题义说明。按定义层级选择名称：
   - 一级定义直接使用原始数据，必须标注官方原始变量名；跨期官方名称不同时，注明对应时期。
   - 二级及以上定义使用已定义结果，必须标注直接参与本层计算的已定义变量名，不再展开其上游官方原始变量名。
   - 下载别名只用于 R 和来源映射，不代替定义逻辑中的官方变量名；官方名称从已核实来源及映射取得。

   按实际处理选择写法：

   | 实际处理 | 写什么 |
   | --- | --- |
   | 原有含义、分类或数值不变 | 说明保留什么 |
   | 重新分类 | 写清哪些回答归入哪类 |
   | 换算或合成 | 写清计算方法、单位及必要权重 |
   | 只统一代码或标签 | 说明保留的含义；具体取值放“分类”，不重复整套对应 |
   | 使用已定义变量 | 用成分名称及对应已定义变量名说明使用什么，从其结果继续计算或判定，不重复已说明的计算过程 |

   成分尚未定义时，先明确其定义及实际依赖，再按上述层级规则写作。引用已定义结果时，写清本层如何使用这些结果，以及本层的适用条件和完整性要求；成分本身的说明不足时，补到该成分的定义逻辑中，不在上层重复展开。

2. **范围说明放在对应方法旁。**
   - 涉及不同对象、时期或来源时，写清适用范围及必要选用顺序。
   - 方案中有共同处理时，只写与当前变量有关的部分；成分中已说明的处理按上面的引用规则表达，不逐项复制整段共同处理。
   - 跨期官方变量名不同时，在对应方法旁用括号紧凑列出名称及时期。共同前缀或后缀明确时可以简写，但不得混淆实际变量名及适用时期。无法明确简写时列出实际名称。逐期完整对应保留在来源记录和映射中。
   - 时期和简写范围依据已核实来源确定。突出实际差异，不为重复对应关系逐年铺表。
   - 同一变量保留跨期口径差异时，定义概括共同概念并点明差异，定义逻辑分别说明各期取值，注意点说明比较限制。是否合并按[跨期结果合并](../stages/01-source-plan.md#跨期结果合并)，不在写作时自行拆分。
   - 不用“按当期题义对应”“依口径处理”代替具体说明。

3. **缺失说明只写以下三类，放在对应方法旁。**

   | 情况 | 写什么 |
   | --- | --- |
   | 完整性要求 | 写清需要哪些回答有效才能计算，例如“六项均有效时才计算” |
   | 缺项计算、补值或折算 | 写清适用条件、允许的缺项范围、处理方法及计算边界 |
   | 依据上游前置题补0或设为缺失 | 写清触发回答、组合关系、适用时期和必要例外 |

   原始缺失、拒答、不知道和特殊编码的缺失转换，不专门写进定义逻辑。不写笼统的“其余记为 NA”。

   异常值剔除和数据一致性校验留在方案和 R 中。若处理包含影响结果含义的阈值、截断或替代，按上方要求写明该方法。

所有条件都来自已确定方案，原始回答用真实选项。调查提问流程放问卷；使用限制放注意点；防报错的程序细节留在代码。不为完整形式增加背景或步骤。

**格式要求**：

- 二级标题用“Criteria”；三级标题用实际变量名；四级标题依次为“定义”“定义逻辑”“分类”“注意点”。
- 变量名及代码格式见[通用格式](../stages/03-copy.md#通用格式)。
- 多步定义用①②③分项。
- 分类用短横线，取值、编码及类别用方括号。
- 逐项比较实际差异更清楚时，可在栏目内用 Markdown 表格；必要处理仍用短句写清。生成器负责呈现真实表格，不将表格行作为普通段落输出。
- 没有注意点时删除整个栏目。

**模板与实例**：[查看本部分](../../../templates/reader-copy.md#5-criteria每个变量怎样得到)。


**模板**（一个变量一组；此处不预设赋值、补零或缺失处理）：

栏目格式按 [Criteria 要求](#5-criteria每个变量怎样得到)，变量名格式统一见[通用格式](../stages/03-copy.md#通用格式)。

```markdown
## Criteria

### {analysis_var}

#### 定义

{该项 display_name 所表示的含义；带上必要的对象、回顾期或单位。}

#### 定义逻辑

{先讲清题义和处理方法，再按上方层级规则标注变量名：一级用官方原始变量名；二级及以上用直接参与本层计算的已定义变量名。}
{本变量必要的适用条件及例外，放在对应方法旁；缺失说明只按上方三类填写。没有则删除本行。多步定义用①②③分项。}

#### 分类

{分类变量逐项列有效、非缺失取值及含义。NA 不列为分类。数值变量填写类型和单位。}

#### 注意点

{本变量必要的使用说明；没有则删除本栏目。}
```


实际为跨期合并结果时，定位实例“跨期来源的紧凑写法”“同一变量保留跨期口径差异”；实际为合成或前置补值时，定位“计算公式与计算条件”“前置跳题补零”。不把实例的事实套到本主题。

## 标题与摘要任务

- 入口：相关定义含义明确；只改措辞时沿用原已定事实。
- 输入：最终结果名称、数量及已定关系。
- 操作：按下方标题和摘要规则表达；树确实需要新写或修改时进入 [树任务](tree.md)。
- 产出：标题和一个摘要自然段，以及适用的树。
- 验收：各结果可识别、数量正确、不把分组或中间量当输出；文字不能改变方向与时期。
- 失败：清单或关系未定回来源；表述、标记问题留文案。

## 2. 标题

**目的**：让读者识别数据库和主题。

**内容要求**：主题名称准确覆盖实际定义，不扩大范围，也不堆列所有变量。中文与英文含义一致。

**格式要求**：一级标题，使用“数据库 — 中文主题（英文主题）”，不加主题序号。

**模板与实例**：[查看本部分](#2-标题)。

## 3. 摘要：最终得到什么

**目的**：让读者知道本主题定义哪些内容，共多少个变量。

**内容要求**：

- 尽量简短地介绍全部最终变量及总数。每个结果都要点到，允许用简短名称和适当归纳，不必重复完整名称。
- 同类变量按结果维度分组。共同名称放在括号外，括号内用短语列出各变量的对象、时期或指标区别；不能只写宽泛类别或数量代替具体结果。
- 分组按主题实际内容确定；内容较少时可直接列名。直接列名且有综合结果时，先介绍综合结果及其分类，再介绍分项；分组介绍时按内容关系安排顺序。

- 结果关系交给下面的关系树；具体定义、适用条件、单位、得分方向及赋值和计算方法写在对应变量的 Criteria；跨变量或整个主题的使用限制写在小book。
- 摘要只保留识别不同结果所需的对象、时期或指标词，不展开上述解释。
- 是否展示关系树按[入口的使用条件](../stages/03-copy.md#关系树)判断；完整模式的Criteria仍须独立讲清变量的含义和取值方法。

**格式要求**：

- 二级标题用“摘要导读”。
- 摘要文字写成一个自然段，不拆成表格或逐行列表。
- 需要关系树时，将树放在该段之后。
- 每个最终变量用①②③编号，编号在整个摘要内连续。按结果维度分组或直接列名时均须编号；分组本身不编号。
- 分组写法：`本主题定义 **数量** 个变量：**共同维度**（①具体结果、②具体结果）；**另一维度**（③具体结果）。` 括号内可用斜杠归纳共同表述。
- 直接列名写法：`本主题定义 **数量** 个变量：①“**结果一**”、②“**结果二**”、③“**结果三**”。`
- 分组名称用 `**加粗**` 标记，不另加引号。直接列出的完整结果名称用中文双引号，其中概念用 `**加粗**` 标记。
- 括号内并列结果用顿号分隔，组间用分号分隔；直接列名时用顿号，“和”或“或”前不再加顿号。
- 数量只加粗数字，不加粗量词。
- 同一概念只强调首次出现；共享的结果维度也要明确标记。

## 3. 摘要：最终得到什么

**模板**（一个自然段，尽量简短地交代每个最终变量和总数；允许按共同维度归纳，算法、时期差异和使用限制写入各自栏目）：

```markdown
## 摘要导读

本主题定义 **{数量}** 个变量：**{共同维度一}**（①{具体结果}、②{具体结果}）；**{共同维度二}**（③{具体结果}）。
```

只合并共同表述，每个结果仍须点到。分组名称按本主题确定；编号连续，不能把分组本身计为变量。有关系树时，完整名称和具体关系由树展开。

**按结果维度分组：饮酒模块**：

```markdown
## 摘要导读

本主题定义 **20** 个变量：**是否饮用**（①过去一年饮酒、②白酒或其他烈酒、③啤酒、④葡萄酒/米酒/黄酒）；**饮酒频率**（⑤过去一年、⑥以前、⑦白酒或其他烈酒、⑧啤酒、⑨葡萄酒/米酒/黄酒、⑩单一酒种最高、⑪所有酒类总体）；**最近一次饮用量**（⑫白酒或其他烈酒、⑬啤酒、⑭葡萄酒/米酒/黄酒）；**饮酒分组**（⑮当前与既往）；**饮酒历程**（⑯开始饮酒年龄、⑰开始饮酒年份、⑱戒酒或减少饮酒次数的年龄、⑲对应年份）；**晨起饮酒**（⑳过去一年是否）。
```

**按结果维度分组：运动模块**：

```markdown
## 摘要导读

本主题定义 **25** 个变量：**是否进行至少 10 分钟活动**（①高强度、②中等强度、③步行、④任一类）；**每周天数**（⑤高强度、⑥中等强度、⑦步行）；**每日时长档**（⑧高强度、⑨中等强度、⑩步行）；**每日估计分钟数**（⑪高强度、⑫中等强度、⑬步行）；**每周估计分钟数**（⑭高强度、⑮中等强度、⑯步行、⑰中高强度）；**活动主要目的**（⑱高强度、⑲中等强度、⑳步行）；**综合活动指标**（㉑最高强度、㉒每周估计体力活动量、㉓休闲活动每周估计活动量、㉔工作活动每周估计活动量、㉕是否以体育锻炼为主要目的）。
```

**少量结果直接列名：总分与分项**：

> 本主题定义①“**是否工作**”、②“**劳动状态**”、③“**过去一个月是否找工作**”和④“**是否办理退休手续**”，共 **4** 个变量。

## 小book任务

- 入口：交付结构、调查设计和共同使用限制已经明确。
- 输入：本次实际结果与已核实的共同限制。
- 操作：按下方选择顺序和基础写法；不把单变量注意点和执行过程搬来。
- 产出：实际提示的独立段落，或约定省略句。
- 验收：首句清楚、解释包含实际影响、不重复已有结论；显示交生成器。
- 失败：未知事实回有关来源；已知事实难懂留本任务，不据此重开全库探索。

## 6. 小book：跨变量或整个主题的使用限制

**内容要求**：

按以下顺序选择内容；没有需要补充的事实时不增加条目。

1. 先说明记录单位和调查设计：一行代表什么，不同时期是否追踪同一批人。人—年长格式说明每行是一个人在某年的记录；系列横断面调查说明各年分别抽样。
2. 再说明本次多个结果共同使用时需要知道的具体差异。写清涉及的结果、时期或对象，差异是什么，以及会怎样影响理解、比较或汇总。不能只写“影响可比性”而让读者自行猜测。

直接说明交付结果，不延伸出无关的去重或统计建议。
- 只影响单个变量的提醒放在该变量的“注意点”；计算方法放在相关变量的“定义逻辑”，缺失说明按该栏目规定的三类范围填写。

**表达要求**：

- 每条先用一句短句点明读者需要知道的事实，再解释必要条件及其对结果使用的影响。首句不重复其他条目已讲清的要点。
- 一条围绕一个要点，句子按[通用表达](../stages/03-copy.md#通用表达)书写。
- 处理影响多个结果或整个主题的使用时，只说明处理后的结果及使用影响，不展开公式、赋值步骤或程序操作。涉及样本纳入范围或结果可比性时，保留必要的时期、对象和例外。文件保存和执行记录不放入小book。

- 不泛泛介绍与交付结果无关的数据库背景，不设想可能的问题或补充通用分析常识。
- 例如，“调查样本会变化”“名册有记录不等于参加访谈”，只有查清与本次结果的具体关系时才写，不能代替尚未查清的事实；但不能因此删掉必要的记录单位、长宽格式和纵向或横断面设计说明。
- 没有需要补充的信息就省略，不为了凑提示另找问题。

同一使用限制已在前文或其他条目讲清，且没有需要补充的共同使用影响时，不再重复。确需补充时，只写新增的事实及影响，不换个说法重述已有结论。不汇总各变量的注意点，不搬入探索过程或 QA 计数。只写实际需要提醒的事项，不凑类型或数量。

**格式要求**：

- 二级标题为“小book提示”。
- 每条一段，条目之间空一行。生成器按顺序显示 `1. `、`2. `，只有一条也编号；文案已有编号时，生成器先识别编号，再统一显示。
- 首句以中文句号结束，不加粗；生成器将首句显示为数据库主题色，后面的解释使用正文色。
- 编号在左，换行后的文字与该条正文起点对齐，不与编号对齐；颜色与缩进由生成器统一处理，文案不手写样式。
- 没有需要单独提醒的事项时，正文写固定句“本主题没有需要单独提示的主题级边界”，生成器会省略卡片。

**模板与实例**：[查看本部分](../../../templates/reader-copy.md#6-小book跨变量或整个主题的使用限制)。


**模板**（有必要的数据结构、调查设计说明或具体发现时替换省略句；下列实例不是每篇都要凑齐的提示类型）：

```markdown
## 小book提示

本主题没有需要单独提示的主题级边界
```

每条独立成段，多条之间空一行。可以按以下示例写编号；固定生成器负责最终顺序编号和缩进，只有一条也显示 `1. `：

```markdown
1. {用短句点明本条事实，不重复其他条目的要点。}{必要条件及对结果使用的影响；涉及处理时只说明处理后的结果，不展开计算或赋值步骤。保留时期、对象和例外。}

2. {另一项确实值得补充的事实，没有则删除本条。}{必要解释；不重复上一条结论，不加入文件保存或程序操作。}
```

首句不加粗，生成器自动使用数据库主题色；后面的解释保持正文色。编号独立在左，换行与正文起点对齐，不靠空格排版。

- 入口：本次实际采用方法或限制资料，或修改该栏。
- 输入：已核实材料及实际用途。
- 操作：按下方规则和模板写资料支持什么，不补填探索历史。
- 产出：实际资料列表；没有则省略本节。

## 7. 参考资料说明

**目的**：说明采用的方法或解释限制有什么依据，哪些是本项目另作的选择。

**内容要求**：

- 只列实际支持公式、计分、分类、阈值或解释限制的已核实材料。
- 每条说明材料讲了什么、支持本主题哪部分；必要时说明它没有规定、由本项目决定的处理。
- 没有实际使用的方法资料时省略本节，不为填满栏目补文献。
- 普通应用文章留在探索记录；已在问卷展示的调查事实不再重复列作方法文献。
- 检索失败、访问过程和检查结论留在探索或执行记录。本节只说明实际采用的资料及其用途。

**写入方式**：在二级标题“参考资料说明”下，每份材料单独写一行，包含材料名称、链接和简短用途。材料名称写明实际项目及年份、调查周期或版本，让读者能区分各份材料。没有链接时给版本和页码，不编造地址。

**生成方式**：生成器按材料顺序统一输出`> 1. `、`> 2. `，每条一行，条目之间不空行。文案无需手写编号；已有编号由生成器整理，不重复编号。

**模板与实例**：[查看本部分](../../../templates/reader-copy.md#7-参考资料说明)。


**模板**（每份材料写一行，无需手写编号；没有实际使用的方法资料时，省略整节。检索和访问过程留在探索记录）：

```markdown
## 参考资料说明

{材料名称、版本或年份及页码}说明{相关方法或限制}。本主题据此{具体采用之处}；{必要时说明本项目另作的决定}。

```


## 组装任务

- 入口：本次范围内正文和必要展示字段已完成。
- 输入：唯一完整稿、当前来源记录、已有有效结论与本次范围。
- 操作：按下方展示顺序组装，再执行入口的检查与交接。
- 产出：完整文案和实际检查结果；只读任务只交发现。
- 验收：改动范围正确，检查证据对应当前文件；通过不代表程序未检查的语义也通过。
- 失败：按表达、事实、实现或显示问题返回相应任务/阶段，不重启未变全流程。

## 1. 文案组成与顺序

下表是`文案.md`的展示顺序，不是业务决策或编写顺序。有条件的部分按实际情况写，不为凑齐栏目增加内容。

| 组成 | 让读者明白什么 | 何时填写 |
| --- | --- | --- |
| 标题 | 这是哪个数据库、什么主题 | 必填 |
| 摘要导读 | 定义哪些内容，共多少个变量 | 必填；结果关系按需另用关系树展示 |
| 定义依据 | 有哪些适用标准，为什么采用本次定义 | 采用量表、诊断、分类或综合指标的标准时填写；按[依据展示判断](../stages/03-copy.md#依据展示判断)决定展示一套标准还是比较多套方案 |
| 问卷 | 帮助理解结果取值所依赖的题义和提问条件 | 定义依赖跳题、多题关系，或原题能消除关键歧义时展示相关部分 |
| Criteria | 每个变量的含义、取值方法及必要限制 | 完整模式每个最终变量都填；省略范围见[模块展示例外](../stages/03-copy.md#模块展示例外) |
| 小book提示 | 多组结果或整个主题使用时要注意什么 | 有这类提醒时填写；没有则使用约定的省略句 |
| 参考资料说明 | 定义方法有哪些依据 | 有实际使用的方法资料时填写；没有则省略该节 |

生成后的笔记会把小book移到问卷之后，并自动加入图表和附件；这些不用手写进文案。
