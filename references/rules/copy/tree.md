# 关系树任务

入口：已满足 [树使用条件](../stages/03-copy.md#关系树)，或用户指定修改树。
输入：现有 `definition_plan`、`approved_analysis_vars`，以及已确认的最终取值或单位、时期、组成和计算关系。对照已写清的 Criteria，保持含义和取值一致。
操作：先读[通用表达](../stages/03-copy.md#通用表达)和[最终变量名称与展示顺序](../stages/01-source-plan.md#最终变量名称与展示顺序)，再读本任务完整写法，按下方顺序填写已选模板；普通分支树用缩进列表，树线由共用程序生成。
产出：可解析且与结果一致的树；不由树增加变量或改变定义。
验收：语义判断关系和范围；程序检查标记与实际可检查对应；显示效果归第5步。
失败：关系未定回来源；标记或排列问题留文案；正确标记的转换/显示问题回生成。

## 关系树


### 编写顺序

1. **先核对分组和顺序，再选结构。** 按[最终变量清单](../stages/01-source-plan.md#最终变量名称与展示顺序)完成本次展示规划，再从下表选一种模板。根节点和分支表达本主题的实际关系，不按模板增减最终变量。
2. **先核对显示名，再填写节点。** 按 `approved_analysis_vars` 定位方案项，核对中文名称和已核实的通行缩写。有缩写时写成“中文名称（缩写）”，如“体质指数（BMI）”。先将核对后的名称保存到 `display_name`，再连同 `analysis_var` 填入 result。同一行填写类别说明或单位 meta。计分结果使用计分后的值，不使用原问卷选项。
3. **补齐关系和适用范围。** 展开理解组成所需的中间项，注明实际合成方法和必要条件。时期及例外放在其适用的树或分支旁。组名与中间项不计为输出变量。
4. **对照方案和 Criteria 核对树。** 核对名称、组成、计算关系及适用时期，然后放入摘要之后。Criteria、R 中的 `analysis_vars` 和 `result_labels`、分析字典继续使用同一份已确认清单；生成器读取这份文案，不在 R 或主题脚本中另写树的排版逻辑。

缺少名称、取值、单位或关系事实时，先核实方案中对应项；已有事实未变时直接使用，不新建一份树专用变量清单。

### 选择结构

同一主题默认用一棵树。主题内的内容分组放在树内分支，不各设标签。只有包含两个或更多独立、平行的主题定义时，才分别画树并设置标签。

| 要说明的关系 | 优先结构 | 内容安排 |
| --- | --- | --- |
| 同一主题包含分项、总分、分类或辅助结果 | 主题为根 | 组成、总分、辅助结果并列；分类放在对应总分下 |
| 多个并列结果按内容分组 | 主题为根 | 内容组下列出具体结果；组名不计为输出变量，不添加不存在的计算关系 |
| 一个综合结果有多层组成 | 综合结果为根 | 依次展开领域和分项；在实际计算发生的层级说明算法 |
| 少量条目合成或划分结果 | 条目 → 计算 → 结果 | 展示输入、运算和输出；分类接在对应结果下 |

多种结构都适用时，选择能完整说明关系且重复最少的一种。不为套模板增加层级。

### 节点与计算关系

- 最终结果直接写成 `[[result:{analysis_var}|{display_name}]] [[meta:{类别说明、范围或单位}]]`。代码名只用于核对，不显示在树中。分析字典 `Label` 与树共用已确认的名称和单位，按[字典标签规则](../stages/01-source-plan.md#最终变量名称与展示顺序)生成；不把类别、范围或时期 meta 当作单位。
- 从上到下、同一行从左到右读取 result 节点，重复引用只保留首次出现，其顺序须与[最终变量清单](../stages/01-source-plan.md#最终变量名称与展示顺序)一致。核对全部最终结果均已表示；不把组标题或中间量标为 result。
- 没有通行缩写时不自造。保留必要的化合物编号；没有可靠中文名称时，保留原名，不猜译。
- 旧成果只有字典名称时，先按变量身份和定义核实中文显示名，再填入方案。保留样本、异构体等必要区别；单位放在 meta，不在名称中重复。
- 主题根节点表示主题，不计为输出变量；综合结果根节点表示实际输出结果。
- 展开组成的具体子项，不用条目数量代替子项名称。
- 合成结果写清各成分怎样运算，分类结果写清判定条件。公式所用符号和必要单位在对应节点内说明。
- 同一组分项产生多个结果时，共同条目展开一次；各结果写清选用哪些条目、怎样计算。
- 同名领域使用不同指标时，分别写清组成。是否属于同一跨期结果，按[已定方案](../stages/01-source-plan.md#跨期结果合并)处理，不只凭名称决定。
- 需要展示中间计算量时，注明其不单独输出。摘要总数只统计最终输出变量。
- 来源有助定位时，在对应节点旁写原始变量或题号。来源名称不另作计分成分。
- 只写已确定的算法。不把占位提示或“待确认”写入正式树。

### 填写 meta

每个最终结果和展开的计分子项都在输入中填写 meta，具体内容及显示方式见下表。

| 节点表示什么 | 说明内容 | 生成后的示例 |
| --- | --- | --- |
| 最终分类变量 | 按方案顺序用简短中文列出类别，`0/1`可保留。最多列前 5 类，超出加“……”。 | `（男／女）`、`（0/1）` |
| 最终连续变量 | 有单位时显示单位；无单位时省略单位说明 | `（kg）`、`（mmHg）` |
| 中间计分项 | 计分后的范围或单位 | `（0–3 分）` |
| 原始回答或测量值 | 原始选项、范围或单位 | 回答确为是／否时写 `（是/否）`；体重写 `（kg）` |

- 类别说明写在该变量节点的 meta 内，不以“二分类”“5类”等数量替代，不展开为类别子分支。上文“分类放在对应总分下”指独立的分类结果变量，不指它的取值类别。
- meta 只作展示，不改变数据分类值；不列 NA。前 5 类的限制不影响方案、Criteria、字典和数据中的完整分类。
- 确认无单位的结果在 `tree` 输入中用 `[[meta:无单位]]` 表明；程序不生成这段文字或括号。已有“无量纲”按同样方式处理，不把漏填单位当作无单位。
- 节点名称、meta 和计算关系须表示同一内容。不得混用原始回答与计分结果。
- 需要提示反向计分时，在对应子项旁注明。

### 放置范围说明

| 说明适用于哪里 | 放在哪里 |
| --- | --- |
| 整棵树的时期 | 首行标题旁；每棵树分别注明 |
| 整棵树的人群、年龄、完整性条件或得分方向 | 标题下、分支前；没有则省略 |
| 某个分支的条件、时期或来源差异 | 对应分支旁；不要扩大到整棵树 |
| 完整重编码、补值步骤、质量核查 | 实现和质量核查留在 R；直接影响结果的补值条件按 Criteria 的缺失说明展示，不放进树 |
| 问卷进入条件和跳转 | 对应问题块，不由关系树代替 |

共同条件不作为组成子项，也不代替各计分子项的取值说明。树中只保留理解关系所需的简短条件。

### 格式要求

1. 普通分支树独占一个 `tree` 代码围栏，起始行写成“```tree 简短标签名”。首行写主题或结果名称；分支用 `- ` 开头，每深入一层增加两个空格。
2. 标签使用实际主题或独立量表的简称。只有一棵树也写标签。
3. 树内不插空行。不同围栏之间留一行空白。
4. 时期使用 period，如 `[[period:1993-2022年]]`；取值、范围和单位使用 meta，如 `[[meta:是/否]]`、`[[meta:0–8 分]]`、`[[meta:kg/m²]]`。这些标记的外层括号由程序生成。
5. 用以下标记说明文字作用。新写或修改的树须标记最终变量和 meta；涉及组成或计算说明时使用对应标记。

| 文字作用 | 写法 |
| --- | --- |
| 最终定义变量 | `[[result:定义变量名|结果名称]]` |
| 组成部分或中间计分项 | `[[component:名称]]` |
| 计算关系、阈值或条件 | `[[relation:说明]]` |
| 取值、范围、单位或来源 | `[[meta:说明]]` |
| 时期 | `[[period:1993-2022年]]`；生成后仍使用现有 meta 显示样式 |

- 不嵌套标记，不跨行标记，不写颜色或 HTML。
- 新写或修改的树逐个填写最终变量身份；同一变量再次引用时沿用同一代码名。旧树未填写身份时，检查器只作已确认显示名或紧邻 meta 的精确匹配，不能猜测或按位置配对。
- 主题标题不因位于根节点就标为 result。
- 共用读取器根据列表层级生成树线、延续竖线和线后空格。节点身份由 result 等标记确定，不根据层级猜测。
- 右侧汇合图继续使用 `text` 围栏，按可见文字宽度对齐连接点；时期用 `[[meta:[1993-2022年]]]`。旧的 `text` 树继续原样读取，不自动推断或改写层级。

显示样式和未修改旧树的显示兼容由[第5步关系树显示](../stages/05-generate.md#关系树显示)统一规定。写作只提供上述内容和语义标记；新写或修改的树仍遵守本节格式。




选定结构后，从 [关系树模板](../../../templates/reader-copy.md#关系树模板) 只取对应骨架或实例：并列结果按内容分组、同主题多种结果、多层综合结果、少量输入合成。没有右侧汇合时，不加载汇合示例。基础语义标记已在本任务，不必为标记语法读完整实例集。
